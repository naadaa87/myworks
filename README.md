# 마이웍스 (MY WORKS)

일이 스스로 굴러가는 업무 시스템.

1인 사업가·프리랜서·소규모 팀을 위한 업무 관리 웹앱입니다. **나의 프로젝트·업무**를 중심에 두고, 함께 일하는 **사람**(직원·협력사·현장 근무자·고객)과 **AI**(클로드)를 그 주변에 연결합니다. 워크스페이스마다 데이터가 분리되고, 어떤 기기에서든 같은 아이디로 들어와 일합니다.

- **지금은 무료 공개 기간** — 결제를 시작하기 전까지 기본 기능과 확장판을 모두 무료로 씁니다.
- **기본 기능** — 홈(오늘 결정할 것)·플랜·프로젝트·매장·업무보드·거래(견적·납품·청구)·돈(수입·지출)·사람(구성원·연락처)·클로드 연동·백업.
- **알림·연결** — 알림함과 휴대폰 푸시 알림, 문자·알림톡 보내기(내 솔라피 계정), 홈택스 세금계산서·현금영수증 자동 수집(마이택스), 한 줄로 넣는 빠른 입력·찾기.
- **확장판** — 필요한 것만 켜서 씁니다.
  - **마이스토어** — 음식·카페, 소매·무인매장, 예약형 매장, 공간대여·숙박: 예약 → 오픈·마감 점검 → 일 마감 → 시설·소모품 → 리뷰 → 지점별 손익
  - **마이셀러** — 온라인 판매: 주문 → 송장 일괄 처리 → 옵션별 재고 → 발주·입고 → 반품·교환 → 문의 → 손익·정산 대사
  - **마이택스** · **마이피플** — 손익·현금 흐름·KPI와 세금 준비 / 파트너 관리와 근무·급여
  - **마이마케팅** — 광고·홍보: 채널·캠페인 → 성과 모으기 → 최적화(고칠 것·설정 안내) → 부스터(예산·입찰·소재 실행안) → 효과 확인
  - **마이크리에이터** — 유튜버·인스타그래머·블로거: 채널 → 협찬 건(문의 → 계약 → 제작 → 게시 → 정산) → 조건 확인서·결과 보고서 → 미디어킷(문의 받기) → 수익 → 단가·견적
- **확인 링크** — 계정이 없는 상대도 링크 하나로 견적 승인, 납품 확인, 청구서 확인, 발주서 확인을 할 수 있습니다.
- **AI 접속** — 개인 토큰으로 클로드를 커넥터(MCP)로 연결하면 "오늘 뭐 해야 해?"에 내 데이터로 답하고, 업무·메모·연락처 변경을 **제안**합니다. 제안은 홈의 **오늘 결정할 것**에서 승인해야 반영됩니다.
- Cloudflare Pages + D1 위에서 동작하며, 화면 클릭만으로 배포·운영할 수 있습니다. 서버 없이 `app/index.html`만 열면 이 브라우저에만 저장하는 로컬 모드로 동작합니다(확장판·거래·AI 접속·확인 링크는 서버 연결이 필요합니다).
- 공개 홈페이지(`/`)에 서비스 소개·가격·가이드·공지가 있습니다. 마이웍스를 대표 서비스로 두고 마이스토어·마이빌딩·마이택스·마이셀러로 넓히는 계획은 홈페이지와 통합 기획 문서에 적혀 있습니다.


## 주소 체계 (2026-10-31부터)

정식 주소는 **https://myworks.ai.kr** 입니다(2026-11-02 연결). 예전 주소 `myworkspro.pages.dev`와 `www.myworks.ai.kr`로 들어오면 같은 경로의 `myworks.ai.kr`로 자동 이동합니다. 서버(`/api/*`)와 AI 접속(`/mcp`)은 예전 주소로도 그대로 응답하므로 이미 연결해 둔 AI 커넥터는 끊기지 않습니다. 브라우저는 주소마다 로그인을 따로 기억하므로 새 주소에서 한 번 다시 로그인하면 됩니다.

| 주소 | 무엇 | 비고 |
|---|---|---|
| `/` | 공개 홈페이지 — 소개 · 서비스(마이스토어·마이빌딩·마이택스·마이셀러·마이피플·마이마케팅·마이크리에이터) · 가격 · 가이드 · 공지 · 약관 | 로그인된 기기에서 열면 자동으로 `/app/`로 이동합니다. 소개 페이지를 보려면 `/?site=1` |
| `/app/` | 마이웍스 앱(워크스페이스) | 예전의 `index.html`이 그대로 옮겨 온 것입니다 |
| `/link/<토큰>` 또는 `/app/#/link/<토큰>` | 확인 링크 | 예전에 보낸 `/#/link/<토큰>` 주소도 그대로 동작합니다 |
| `/join/<토큰>` → `/app/#/invite/<토큰>` | 사람마다 만드는 초대 링크 | 한 번만 쓰고, 받은 사람이 아이디를 만들면 승인 없이 바로 참여합니다 (2026-11-17) |
| `/#join=<코드>` · `/app/#join=<코드>` | 팀 초대 코드 | 관리자 승인 후 합류. 둘 다 동작합니다 |
| `/?ref=<소개 코드>` | 소개 링크 | 홈페이지가 코드를 60일 동안 기억했다가 회원가입에 넘깁니다 |
| `/app/#signup` | 회원가입 화면 바로 열기 | 홈페이지 ‘시작하기 → 회원가입 하러 가기’가 이 주소로 연결됩니다 |
| `/admin` → `/app/#/admin` | 총괄관리(운영자·운영팀 전용) | 운영자나 운영팀 계정으로 로그인해야 열리고, 보안 키를 넣어 두었다면 한 번 더 묻습니다. `/app/#/admin/fb`처럼 탭을 바로 열 수도 있습니다 |
| `/api/*` · `/mcp` | 서버 | 변동 없음 |
| `/features` · `/faq` · `/about` | 기본 기능 · 자주 묻는 질문 · 회사 소개 | 2026-11-16 추가 |
| `/blog/` · `/blog/<글 주소>` | 블로그(업무 노트) | 글은 `src/site/content.js`에 있습니다. 새 글을 더하면 목록·사이트맵·RSS에 자동으로 들어갑니다 |
| `/sitemap.xml` · `/rss.xml` · `/robots.txt` | 검색엔진용 파일 | 생성기가 함께 만듭니다. 없는 주소는 `404.html`이 열립니다 |

**검색엔진 등록** — 네이버 서치어드바이저 소유확인 태그(`naver-site-verification`)는 생성기의 `NAVER_VERIFY` 상수로 모든 페이지 `<head>`에 들어갑니다. 구글 서치콘솔과 Bing은 DNS로 확인했습니다. 네이버에는 `https://myworks.ai.kr/sitemap.xml`과 `https://myworks.ai.kr/rss.xml`을 제출합니다. 페이지마다 대표 주소(canonical), 공유용 정보(Open Graph), 구조화 데이터(JSON-LD)를 넣습니다.

**블로그 글 쓰는 법** — `src/site/content.js`의 `ARTICLES` 맨 앞에 글을 하나 더하고(`slug`, `cat`, `date`, `title`, `desc`, `tags`, `svc`, `body`) 생성기를 다시 돌립니다. 기능 설명은 이 README와 어긋나지 않게, 준비 중인 기능은 ‘예정’이라고 적습니다. 수치는 출처가 있는 것만 쓰고 `refs`에 남깁니다.

홈페이지 파일은 저장소 루트(`index.html`, `store.html`, `pricing.html` … `site/`)에, 앱은 `app/index.html`에 있습니다. 홈페이지 문구는 `src/site/gen.js`를 고쳐 다시 생성하거나, 급하면 HTML 파일을 직접 고쳐도 됩니다(다음 생성 때 덮어쓰이므로 `gen.js`에도 반영해 두세요).

## 이번 버전 올리는 방법

Cloudflare 설정(D1 연결)은 그대로 두고, GitHub에서 파일 두 개만 바꾸면 됩니다. 앱은 `app/index.html`, 서버는 `functions/_middleware.js`입니다. 기존 데이터는 그대로 이어지고, 필요한 표(테이블)와 칸은 서버가 첫 요청 때 스스로 추가합니다. SQL을 입력할 일은 없습니다.

1. **앱 파일 교체** — 저장소(`naadaa87/myworks`)에서 `app` 폴더를 연 상태로 `Add file → Upload files`를 누르고 새 `index.html`을 끌어다 놓은 뒤 **Commit changes**. 같은 이름이면 덮어써집니다. (루트의 `index.html`은 공개 홈페이지 첫 화면이므로 여기에 앱 파일을 올리지 마세요.)
2. **서버 파일 교체** — 저장소에서 `functions` 폴더를 연 상태로 `Add file → Upload files`를 누르고 새 `_middleware.js`를 끌어다 놓은 뒤 **Commit changes**. 폴더 안에서 올려야 그 자리의 파일이 바뀝니다.
3. **(선택) README.md**, `sample-claude.json`도 같은 방법으로 올립니다.
4. 1~2분 뒤 자동 배포가 끝나면 사이트를 엽니다. 처음 접속하는 순간 운영자 워크스페이스에는 마이스토어가 자동으로 켜집니다. 마이셀러는 왼쪽 메뉴 **확장판**에서 켭니다.
   - 아직 운영자 계정이 없다면(처음 설정) **운영자 계정 만들기** 화면이 나옵니다. 예전 로컬 데이터는 같은 화면의 **백업 파일로 시작**으로 옮깁니다.
   - 이전 버전(v1) 서버에서 쌓인 데이터도 그대로 이어집니다. 구성원은 다시 로그인하면 됩니다.

> 운영자 계정은 플랫폼에서 하나이며, 처음 설정한 사람이 갖습니다. 다른 워크스페이스의 등급·모듈은 총괄관리에서 운영자가 정합니다.

### 선택: 바인딩 두 개 더 (쏘플 운영용)

아래 두 가지는 필요할 때만 연결합니다. Pages 프로젝트 → **Settings → Bindings → Add → D1 database**에서 이름과 데이터베이스를 고른 뒤 저장하고, **Deployments → 최신 배포 → Retry deployment**.

| 변수 이름 | 연결할 데이터베이스 | 쓰임 |
|---|---|---|
| `HOSTDB` | 예약 사이트가 쓰는 DB (예: `ssople-host`) | 호스트 예약 자동 동기화. 읽기만 하며, 운영자 워크스페이스에서만 쓸 수 있습니다. |
| `SPACEDB` | 예전 공간관리 시스템 DB (예: `ssople-ops`) | 따로 쓰던 마이웍스 스페이스 데이터를 한 번 옮겨 올 때만. 다 옮긴 뒤에는 바인딩을 지워도 됩니다. |

## 이용 흐름

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 1. 회원가입 | 새 사용자 | 첫 화면 **회원가입**에서 워크스페이스 이름·이름·아이디·비밀번호·연락처를 입력해 개설을 신청합니다. |
| 2. 개설 | 운영자 | 가입 방식이 **자동 개설**이면 승인 없이 바로 열립니다. **승인 후 개설**로 두었다면 **총괄관리 → 가입·베타**에서 신청 내용을 확인하고 승인합니다. 베타 코드를 넣고 가입한 경우에도 바로 열립니다. |
| 3. 로그인 | 사용자 | 승인되는 즉시, 어느 기기에서든 같은 아이디·비밀번호로 로그인해 본인 워크스페이스를 씁니다. |
| 4. 팀원 합류 | 워크스페이스 관리자·직원 | 사람 메뉴나 프로젝트 화면의 **사람 초대**에서 연락처를 고르면 사람마다 초대 링크가 만들어집니다. 카카오톡·문자·메일로 보내면 받은 사람이 아이디를 만들고 승인 없이 바로 참여합니다. 여러 사람에게 같은 주소를 보내는 **팀 초대 코드**(관리자 승인)와 아이디 직접 발급도 그대로 있습니다. |
| 5. 확장판 켜기 | 워크스페이스 관리자 | 왼쪽 메뉴 **확장판**에서 마이스토어·마이셀러·마이택스·마이피플·마이마케팅·마이크리에이터 가운데 필요한 것을 켭니다. 지금은 무료 공개 기간이라 결제 없이 켤 수 있습니다. |

승인 후 개설 방식에서는 승인 전에 로그인되지 않고, 화면에 "가입 승인을 기다리는 중입니다"라고 안내됩니다. 워크스페이스끼리는 데이터가 완전히 분리되어 서로 보이지 않습니다.

## 등급 — 지금은 무료 공개 기간

결제를 시작하기 전까지 **모든 워크스페이스가 기본 기능과 확장판을 무료로** 씁니다. 화면 곳곳에 ‘무료 공개 기간’이라고 표시되고, 카드 등록은 받지 않습니다. 결제를 시작하기 전에는 앱 공지로 먼저 알립니다. 비공개 베타에 참여한 워크스페이스는 처음 안내한 대로 1년간 가격이 고정됩니다.

| | 무료 공개 기간 (지금) | 결제 시작 뒤 베이직 | 결제 시작 뒤 프로 |
|---|---|---|---|
| 기본 기능 | 전부 (홈·플랜·프로젝트·매장·업무보드·거래·돈·사람·확인 링크·백업) | 전부 | 전부 |
| 구성원 | 본인 + 30명 | 본인 + 2명 | 본인 + 10명 |
| 브랜드·회사 | 사실상 제한 없음 | 2개 | 제한 없음 |
| AI 접속 | 읽기·쓰기 토큰 20개, 제안 → 승인 반영 | 읽기 토큰 1개 | 읽기·쓰기 토큰 20개 |
| 확장판 | 마이스토어 · 마이셀러 (필요한 것만 켬) | — | 마이스토어 · 마이셀러 |
| 확인 링크 | 납품 확인 · 견적 승인 · 청구서 확인 · 발주서 확인 | 납품 확인 | 전부 |

- 운영자가 총괄관리에서 워크스페이스마다 정해 둔 등급·기한·한도는 그대로 저장되어 있다가, 결제를 시작하면 다시 적용됩니다.
- 결제를 시작한 뒤 프로 기한이 지나면 **베이직 규칙**으로 돌아갑니다. 데이터는 그대로 남고 확장판 메뉴만 사라지며, 다시 프로로 올리면 그대로 보입니다. 한도를 넘는 구성원·브랜드는 새로 추가만 막힙니다.

### 확장판 켜고 끄기

워크스페이스 관리자가 왼쪽 메뉴 **확장판**에서 스위치를 켜면 메뉴에 바로 추가됩니다. 끄면 메뉴만 사라지고 데이터는 남습니다. 확장판 데이터는 전체 백업에 함께 들어가고, 복원하면 같이 돌아옵니다. 거래(견적·청구)는 확장판이 아니라 기본 기능이라 항상 켜져 있습니다.

| 확장판 | 이런 분께 | 지금 |
|---|---|---|
| 마이스토어 | 음식·카페, 소매·무인매장, 예약형 매장, 공간대여·숙박 | 사용 가능 |
| 마이셀러 | 오픈마켓·자사몰·도매·공동구매로 상품을 파는 분 | 사용 가능 |

## 처음 화면과 빠른 입력

**시작 안내.** 새 워크스페이스의 홈에서 하는 일을 고릅니다 — 의뢰받아 일해요 / 매장·공간을 운영해요 / 물건을 팔아요 / 콘텐츠를 만들어요 / 여러 가지를 해요. 고른 일에 맞는 확장판이 켜지고 첫 단계 네 가지가 나옵니다. 연락처를 적거나 매장을 등록하면 그 단계는 스스로 끝난 것으로 바뀝니다. 접어 둔 안내는 설정에서 다시 볼 수 있습니다.

**빠른 입력·찾기.** 어디서나 한 줄로 넣고 찾습니다. 왼쪽 **찾기**, 휴대폰 아래 **＋**, `Ctrl(⌘)+K` 또는 `/`.

| 이렇게 적으면 | 이렇게 들어갑니다 |
|---|---|
| `내일까지 견적서 보내기` · `다음 주 월요일 시안 검토` · `11/25 계약서` | 업무 — 날짜는 마감으로. 프로젝트를 정하지 않으면 ‘내 업무’에 담깁니다 |
| `점심 12,000원` · `임대료 150만원` · `커피 4500` | 지출 (돈 메뉴). `입금 110만원 모노가구`처럼 입금·수입·매출이 들어 있으면 수입 |
| `김지수 010-1234-5678` | 연락처 |
| 프로젝트·업무·연락처·메뉴 이름 | 찾기 — 누르면 그 화면으로 |

여러 뜻으로 읽히면 후보를 모두 보여 주고, Enter는 맨 위 것을 고릅니다. 넣은 뒤에도 창이 열려 있어 이어서 적을 수 있습니다.

**휴대폰 메뉴.** 아래 탭은 홈 · 보드 · 입력 · 돈 · 전체 다섯 칸입니다. 나머지 메뉴와 알림·문자·설정은 **전체**에 있습니다.

## 홈 — 오늘 결정할 것

홈 맨 위에 승인·확인이 필요한 일이 모입니다. 여기서 바로 처리하면 됩니다.

| 항목 | 내용 | 버튼 |
|---|---|---|
| AI 제안 | 클로드가 올린 업무 추가·상태 변경·메모·연락처·외주 안건 제안 | 승인 → 즉시 반영 / 거절(사유 기록) |
| 검수 요청 | 담당자가 결과물을 올리고 확인을 요청한 업무 | 승인(업무 완료) / 보완(사유 전달) / 열기 |
| 보완 요청 | 내가 담당한 업무에 보완 요청이 온 것 | 다시 검수 요청 |
| 견적 수정 요청 | 고객이 확인 링크에서 수정을 요청한 견적 | 견적 고치기 |
| 입금 기한 지남 | 기한이 지난 청구서 | 입금 확인 / 청구 링크 |
| 가입·합류 요청 | (운영자·관리자) 승인 대기 | 총괄관리 / 사람 |
| 문의 · 문의 답변 | (운영자) 새 문의 / (모든 구성원) 내 문의에 온 답변 | 총괄관리 / 문의 창 |

### 검수 흐름 (납품 확인)

1. 담당자(직원·협력사)가 업무에서 **검수 요청**을 누르고 납품물 링크("제목 | 링크")와 메모를 적습니다. 업무는 **검토** 상태가 됩니다.
2. 관리자, 또는 그 프로젝트·매장에서 일하는 직원이 홈이나 업무 목록에서 **승인**(완료 처리) 또는 **보완 요청**(사유 전달)을 합니다. 본인이 담당한 업무는 본인이 승인할 수 없습니다.
3. 고객에게 직접 확인받으려면 **고객 확인 링크**를 만들어 보냅니다. 고객이 링크에서 "결과물을 확인했습니다"를 누르면 업무가 완료되고, 수정을 요청하면 사유와 함께 담당자에게 돌아갑니다.

AI가 만든 업무·연락처에는 **AI** 표시가 붙습니다.

## 사람 — 구성원과 연락처

- **구성원** — 로그인해서 함께 일하는 사람. 사람 초대 링크, 팀 초대 코드(합류 승인), 아이디 직접 발급 세 가지로 들어옵니다.
- **연락처** — 고객·거래처·외주 등 바깥 사람. 이름·회사·연락처·이메일·구분·그룹·메모를 두고 검색합니다. 거래 메뉴의 안건·견적·청구서는 여기 등록한 고객을 기준으로 만들어지고, 클로드에게 "하나디자인 연락처 알려 줘"처럼 물어볼 수 있습니다. 연락처는 관리자·직원만 보고, 협력사·현장 근무자 기기로는 전송되지 않습니다.

### 연락처 가져오기

사람 → 연락처 → **연락처 가져오기**에서 파일을 올리거나 붙여 넣습니다. 파일은 브라우저 안에서만 읽고, 미리보기에서 고른 사람만 연락처로 저장합니다.

| 가져올 곳 | 파일 만드는 법 |
|---|---|
| 구글 연락처 | contacts.google.com → 내보내기 → **Google CSV**. 라벨은 연락처의 **그룹**으로 붙습니다 |
| 아이폰 | icloud.com/contacts → 연락처 선택 → ⚙ → **vCard 내보내기** |
| 안드로이드 | 연락처 앱 → 설정 → **연락처 내보내기**(.vcf). 안드로이드 크롬에서는 **휴대폰에서 고르기** 버튼으로 바로 고를 수도 있습니다 |
| 네이버·아웃룩·엑셀 | CSV로 내보내기. 첫 줄의 열 제목(이름·회사·휴대폰·이메일·메모 등)으로 열을 맞추고, EUC-KR 파일도 읽습니다 |
| 붙여넣기 | 한 줄에 한 사람. 메일 받는 사람 칸(`홍길동 <hong@mail.com>, …`)을 그대로 붙여도 됩니다 |

같은 이메일이나 휴대폰 번호가 이미 있으면 새로 만들지 않고 빈칸과 그룹만 채웁니다. 한 번에 3,000명까지 가져옵니다.

### 사람 초대 (초대 링크)

1. 사람 메뉴의 **사람 초대**, 프로젝트 화면의 **＋ 초대**, 또는 연락처 목록에서 여러 명을 체크한 뒤 **선택한 사람 초대**를 누릅니다.
2. 사람(연락처에서 검색하거나 이메일·휴대폰 입력), 역할, 함께할 프로젝트, 메시지, 유효 기간(7·14·30일)을 정합니다.
3. 사람마다 다른 링크(`myworks.ai.kr/join/…`)가 만들어집니다. **링크 복사 · 카톡·공유 · 문자 · 메일 · Gmail** 버튼은 내 기기의 앱으로 메시지를 엽니다. 마이웍스 서버가 대신 보내지 않습니다.
4. 받은 사람이 링크를 열어 이름·아이디·비밀번호를 정하면 **승인 없이 바로 로그인**되고, 정한 프로젝트의 참여자가 됩니다. 연락처와도 이어져 연락처 목록에 **참여 중**이 표시되고, 초대한 사람의 활동 기록에 남습니다.

- 관리자는 모든 역할로, 직원은 자기가 담당·참여한 프로젝트에 **협력사**로만 초대합니다.
- **보낸 초대**에서 보냄 · 열어 봄 · 참여함 · 기한 지남 · 취소함을 보고, 다시 보내기·취소·다시 열기를 합니다.
- 구성원 수 한도(베이직 2명)를 넘으면 링크를 열어도 참여할 수 없다고 안내합니다.
- 지금 아이디는 워크스페이스 하나에 속합니다. 이미 다른 워크스페이스 아이디가 있는 사람도 초대받은 곳에서 쓸 아이디를 새로 만듭니다.

### 마이웍스 소개하기

사람 메뉴의 **마이웍스 소개하기**에 워크스페이스마다 소개 링크(`myworks.ai.kr/?ref=코드`)가 있습니다. 이 링크로 들어와 가입하면 소개한 워크스페이스가 기록되고, 몇 곳이 가입했는지 보입니다. 운영자가 총괄관리 → 가입·베타에서 **소개 보상** 일수를 정하면, 소개로 열린 워크스페이스와 소개한 워크스페이스 모두 프로 기한이 그만큼 늘어납니다(한 번만, 0이면 보상 없음). 초대받아 들어온 협력사의 홈에는 **내 워크스페이스 만들기** 안내가 나옵니다.

## 마이스토어 — 매장·공간 운영

매장과 공간을 하루 단위로 굴리는 확장판입니다. 왼쪽 메뉴 **마이스토어**에서 씁니다.

```
예약·영업 → 오픈·청소·마감 점검(근무자 휴대폰) → 일 마감(매출·시재) → 관리자 확인 → 지점별 손익 → 돈 메뉴
```

### 업종 네 가지

처음 열면 업종을 고릅니다. 고른 업종에 맞춰 오픈·마감 점검 항목과 일 마감 결제수단이 준비되고, 지점마다 업종을 따로 정할 수도 있습니다.

| 업종 | 예 | 중심 기능 |
|---|---|---|
| 음식·카페 | 식당 · 카페 · 주점 · 배달 전문점 | 오픈·마감 점검, 일 마감(카드·현금·계좌이체·배달앱·간편결제) |
| 소매·무인매장 | 편의점 · 무인 아이스크림·카페 · 꽃집 · 반려용품 | 순회 점검, 일 마감, 소모품 부족 알림 |
| 예약형 매장 | 미용실 · 네일·피부관리 · 필라테스·PT · 스튜디오 | 담당자별 시간 예약, 노쇼 기록, 일 마감 |
| 공간대여·숙박 | 파티룸 · 스터디룸 · 연습실 · 게스트하우스·펜션 | 예약이 들어오면 청소 일정 자동 생성, 근무자 체크리스트 |

### 시작하기 (처음 한 번)

1. **업종 고르기** — 현황 첫 화면에서 가장 가까운 업종을 누릅니다. 나중에 설정 → 업종·운영 규칙에서 바꿀 수 있습니다.
2. **운영 지점 켜기** — 설정 → 운영 지점. 마이웍스 매장 가운데 마이스토어로 관리할 곳만 켭니다. 지점마다 업종·영업시간·시작 시재·담당자(예약형)·일 마감 사용 여부와 지역·기본 담당·지점 코드·별칭·청소 규칙을 정할 수 있습니다. **＋ 새 지점**을 누르면 매장도 함께 만들어집니다.
3. **근무자 초대** — 사람 메뉴에서 역할을 **현장 근무자**로 발급하고, 건당 단가와 담당 지점을 정합니다. 근무자는 같은 주소로 휴대폰에서 로그인합니다.

### 메뉴

| 화면 | 내용 |

| 주간 보드 | 요일별 청소·담당·동시 진행 지점 수. 권역(지역) 단위 **일괄 배정**, 그날의 **필수 확인사항** 등록과 읽음 명단. 인쇄·PDF, 단톡 공유용 이미지 저장 |
| 청소·점검 | 기간·지점별 일정과 담당 지정 / 확인·피드백(미체크 항목 확인 후 확인 완료 또는 보완 요청) / 체크리스트 항목(청소·오픈·마감) |
| 일 마감 | 지점·날짜별 결제수단 매출, 손님 수, 시작 시재·지출·마감 시재와 시재 차이. 근무자가 제출하고 관리자가 **확인**하면 잠깁니다 |
| 예약 | 공간 대관은 예약 달력(낮·밤·올데이 칸을 눌러 바로 등록)과 엑셀 업로드, 예약형 매장은 담당자별 **시간 예약**(확정·완료·노쇼·취소) |
| 시설·소모품 | 고장·오염·구매 필요 신고와 처리 기록 / 소모품 남은 수량·최소 수량·거래처, 부족 알림 |
| 채널·리뷰 | 지점별 홍보 채널 점검일 / 플랫폼 리뷰·문의 기록과 답글. 자주 쓰는 답글 문구와 **클로드에게 초안 부탁할 문장 복사** |
| 손익 | 지점별 매출(공간은 예약+일 마감, 매장은 일 마감 기준)·예약률·객단가·채널 분석 / 월 비용 입력과 영업이익, **돈에 기록** |
| 설정 | 운영 지점, 업종·운영 규칙(예약 채널별 수수료율, 리뷰 답글 문구 포함), 근무자·단가, 연결(호스트 동기화·예전 데이터 가져오기) |

### 청소 일정이 만들어지는 규칙 (공간대여·숙박)

- **낮타임**만 있으면 낮 이용 종료 후 정식 청소, 같은 날 **밤타임**이 이어지면 그 사이에 **중간 정리**(빠른 정리 항목)가 잡힙니다. 같은 고객이 이어서 쓰면 중간 정리를 생략할 수 있습니다.
- **밤타임**은 다음 날 아침 퇴실 후, **올데이**는 이용 종료 후 정식 청소입니다.
- 다음 입실 시각에서 **입실 전 버퍼**(기본 30분)를 뺀 시각까지가 청소 가능 시간입니다. 이 시간이 **표준 소요**(기본 120분)보다 짧으면 **긴급**, 다음 입실이 다른 날이면 "~10/8 13:30까지 완료"처럼 마감으로 표시됩니다.
- 예약에 **확인 메모**를 걸면 해당 청소에 "확인 후 진행" 배너가 뜹니다. 근무자에게는 메모 내용이 보이지 않습니다.
- 담당은 카드에서 지정한 사람 → 그날 권역 일괄 배정 → 지점 기본 담당 순으로 정해집니다.

일 마감을 쓰는 지점은 오늘과 내일의 **오픈 점검·마감 점검**이 자동으로 근무자 화면에 올라갑니다.

### 근무자 화면

현장 근무자로 로그인하면 **오늘 할 일**과 **시설·소모품** 메뉴가 보입니다(마이셀러를 켰다면 **오늘 발송**도 함께). 오늘 필수 확인사항을 읽고 **확인했습니다**를 누르면 관리자 보드에 읽음이 남습니다. 카드를 누르면 체크리스트가 열리고, 체크한 내용은 바로 자동 저장됩니다. 마감 점검을 마치면 그 자리에서 **일 마감**(결제수단별 매출·시재)을 적어 제출합니다. 일 마감은 오늘과 어제 것만 적을 수 있고, 관리자가 확인한 날은 고칠 수 없습니다. 소모품은 남은 수량만 고칠 수 있습니다.

근무자에게는 배정됐거나 아직 담당이 없는 일만 보이고, 담당 지점을 정해 두면 그 지점 일만 보입니다. **예약자 이름·연락처·결제 금액·확인 메모는 근무자 기기로 아예 전송되지 않습니다.** 같은 고객이 이어서 쓰는지 판단하는 값만, 매번 다르게 바뀌는 형태로 보냅니다. 리뷰와 소모품 거래처·메모도 근무자에게는 가지 않습니다.

시설 담당은 현황·시설 관리·점검·청소 현황을 보고, 시설 이슈의 상태와 처리 기록을 관리합니다.

### 예약 넣는 방법

1. **예약 달력** (공간대여) — 칸을 누르면 그 지점의 낮·밤·올데이 예약이 바로 들어갑니다(검정). 다시 누르면 상세 정보와 삭제가 나옵니다. **상세 예약 추가**에서는 예약자·연락처·금액·예약번호까지 넣습니다.
2. **시간 예약** (예약형 매장) — 담당자 열과 시간 칸으로 된 화면에서 빈칸을 눌러 예약을 넣고, 시술·수업 내용과 상태(확정·완료·노쇼·취소)를 기록합니다. 담당자 목록은 지점 설정에서 정합니다.
3. **엑셀 업로드** — 예약 사이트에서 받은 월별 엑셀(xlsx)을 올리면 이용일·지점·구분·결제금액 열을 자동으로 찾습니다. 지점 이름이 다르면 화면에서 골라 맞춥니다. **해당 월 교체**는 그 달의 기존 엑셀분만 바꾸고, **기존에 추가**는 같은 예약번호를 건너뜁니다.
4. **호스트 동기화** — `HOSTDB`를 연결하면 오늘 기준 35일 전 ~ 90일 후 예약을 자동으로 맞춥니다. 관리자가 마이스토어를 열 때 마지막 동기화가 12시간을 넘었으면 한 번 돌고, 예약 달력과 설정 → 연결의 버튼으로 바로 실행할 수도 있습니다. 예약 사이트에서 취소된 예약은 여기서도 사라집니다. 지점 이름이 달라 못 맞춘 예약은 운영 지점의 **지점 코드(S코드)**나 **별칭**에 그 이름을 넣으면 다음부터 연결됩니다.

엑셀·동기화로 들어온 예약은 달력에 주황색으로 표시되고, 내용은 원본에서 고칩니다. 예약번호가 N으로 시작하면 네이버, BF로 시작하면 자체 예약으로 집계합니다.

### 마이웍스와 연결되는 부분

- **매장 = 지점** — 마이스토어를 켠 매장이 곧 지점입니다. 매장 상세 화면에 이달 예약·매출·오늘 점검·시설 이슈 카드가 붙고, 꺼져 있으면 그 자리에서 켤 수 있습니다.
- **구성원 = 근무자** — 구성원 수정 창에서 건당 단가와 담당 지점을 정합니다. 단가는 손익의 인건비 자동 계산(제출·확인 완료 청소 × 단가, 기본 15,000원)에 쓰입니다.
- **돈에 기록** — 손익에서 그 달 지점별 매출과 비용(임대료·관리비·소모품·통신비·기타·수수료·인건비)을 각 매장의 매출·비용 기록으로 옮깁니다. 같은 달을 다시 보내면 마이스토어 집계분만 새 값으로 바뀝니다.
- **홈 화면** — 마이스토어 카드에 오늘 점검·청소, 긴급, 담당 미정, 확인 대기, 일 마감, 소모품 부족, 답할 리뷰가 모입니다.
- **주간 리포트** — 연동·데이터의 주간 리포트 복사에 예약 건수·매출, 일 마감, 청소 확인 현황, 진행 중 시설 이슈가 함께 들어갑니다.
- **배정된 업무** — 마이웍스 업무를 근무자에게 배정하면 근무자 화면 아래에 함께 보이고, 체크하면 완료됩니다.
- **백업** — 전체 백업 파일에 마이스토어 데이터가 함께 들어가고, 복원하면 같이 돌아옵니다. 업무 데이터 초기화를 하면 예약·청소·일 마감 기록도 지워지고 운영 시간과 체크리스트 항목은 남습니다.

### 예전 마이웍스 스페이스 데이터 가져오기

따로 배포해 쓰던 공간관리 시스템의 데이터를 운영자 워크스페이스로 옮깁니다.

1. 위 표대로 `SPACEDB` 바인딩을 예전 DB(예: `ssople-ops`)에 연결하고 다시 배포합니다.
2. 운영자 계정으로 마이스토어 → 설정 → **연결** → **가져올 내용 확인** → **가져오기 시작**.
3. 지점·계정·체크리스트·채널·비용·일괄 배정·브리핑·시설 이슈·예약·청소 기록이 차례로 옮겨집니다. 같은 이름의 매장·구성원은 그대로 이어 쓰고, 없는 것은 새로 만듭니다. 여러 번 눌러도 중복으로 들어가지 않습니다.
4. 새로 만들어진 근무자는 아이디가 없는 상태입니다. 사람 메뉴에서 **수정**을 눌러 아이디와 비밀번호를 정해 주면 로그인할 수 있습니다. (예전 비밀번호는 옮기지 않습니다)
5. 다 옮겼으면 `SPACEDB` 바인딩은 지워도 됩니다.

## 거래 — 견적·납품·청구

왼쪽 메뉴 **거래**. 기본 기능이라 항상 켜져 있고, 관리자·직원이 씁니다. 프리랜서 외주, 소규모 B2B 납품처럼 한 건씩 견적을 내고 받는 일을 관리합니다.

```
문의 → 안건 등록 → 견적(확인 링크로 승인) → 진행·납품 → 청구서(확인 링크) → 입금 확인 → 돈 메뉴에 기록
```

| 화면 | 내용 |
|---|---|
| 현황 | 진행 중 안건, 견적 회신 대기, 미수금, 이달 입금. 견적 수정 요청·입금 기한 지난 건을 맨 위에 |
| 안건 | 거래 한 건. 고객(연락처)·납기·예상 금액·요청 내용·계약 조건(범위·수정 횟수·대금 조건). 상태: 문의 → 견적 → 진행 → 납품 → 청구 → 완료 / 보류 |
| 견적 | 항목·수량·단가를 넣으면 공급가·부가세·합계가 바로 계산됩니다. 설정의 **단가표**에서 골라 넣을 수 있습니다. **저장하고 발송 처리**를 누르면 확인 링크가 만들어집니다. 고객이 승인하면 안건이 **진행**으로 바뀌고 승인 견적이 계약 조건에 기록됩니다. 승인된 견적은 고칠 수 없고(무효 처리만), 조건이 바뀌면 새 견적을 만듭니다. |
| 청구·입금 | 청구서를 만들면 세금 처리(부가세 10% 별도 / 3.3% 원천징수 / 없음)에 따라 받을 금액이 계산되고 확인 링크가 만들어집니다. **입금 확인**을 누르면 안건의 청구가 모두 입금됐을 때 자동으로 **완료**가 됩니다. **돈에 기록**을 누르면 돈 메뉴에 수입으로 들어갑니다. |
| 설정 | 보내는 사람(이름·상호·연락처·사업자 구분·사업자번호), 입금 계좌, 계약서 양식 링크, 견적서 기본 안내문, 단가표, 플랫폼 수수료율(크몽·위시켓 등, 참고용) |

클로드가 `create-job` 제안으로 안건을 올릴 수도 있습니다. 연락처에 없는 고객 이름이면 승인할 때 연락처가 함께 만들어집니다.

## 돈 — 수입과 지출

왼쪽 메뉴 **돈**. 관리자·직원이 씁니다. 직접 적은 수입·지출과 거래·마이스토어·마이셀러에서 보낸 기록이 한곳에 모입니다.

- 월을 넘기며 이달 수입·지출·남는 돈과 최근 12개월 흐름을 봅니다.
- 항목별(매출·수수료·재료비 등)과 출처별(직접 기록·거래·마이스토어·마이셀러)로 나눠 보고, 수입·지출만 골라 볼 수 있습니다.
- 위쪽 입력 줄에서 금액·구분·항목·메모를 적으면 바로 기록됩니다. 목록은 CSV로 내려받습니다.
- 홈 화면의 **이달 손익** 카드에 같은 숫자가 보입니다.

## 마이셀러 — 온라인 판매 운영

왼쪽 메뉴 **마이셀러**. 관리자·직원은 전체를, 현장 근무자(발송 담당)는 **오늘 발송** 화면만 씁니다.

```
주문(엑셀 업로드·직접 입력) → 송장·발송(택배 접수 파일 → 송장 파일) → 재고 차감·기록 → 발주·입고 → 반품·교환 → 문의 → 손익·정산 대사 → 돈 메뉴
```

처음 열면 **판매 방식**을 고릅니다. 오픈마켓 판매·자사몰 운영·도매·납품·공동구매·SNS 가운데 고르면 그에 맞는 시작 순서가 현황에 나오고, 필요한 판매 채널(예: 공동구매, 거래처 납품)이 더해집니다. 설정에서 언제든 바꿀 수 있습니다.

| 화면 | 내용 |
|---|---|
| 현황 | 발송할 주문, 답할 문의, 재고 부족 상품, 이달 매출(채널별). 발주 변경 요청·입고 예정·반품·교환 진행이 있으면 맨 위에 |
| 주문 | 기간·상태·채널·검색. **엑셀 업로드**는 스마트스토어·쿠팡 등에서 받은 주문 엑셀(xlsx·csv)의 열 이름을 보고 자동으로 맞추고(수동 조정 가능), 채널별로 맞춤을 기억합니다. **추가**는 같은 주문번호를 건너뛰고, **해당 월 교체**는 그 달의 기존 엑셀분만 바꿉니다. 상품명과 옵션이 모두 같은 상품이 있으면 그 옵션 상품에, 없으면 이름이 같은 상품에 연결됩니다. CSV 내보내기도 됩니다. |
| 송장·발송 | ① **택배 접수 파일**: 발송 대기 주문을 받는분·연락처·주소·품목·수량·배송 메시지·주문번호 CSV로 받아 택배사 대량 접수에 씁니다. ② **송장 파일 올리기**: 택배사에서 송장이 붙은 파일(엑셀·CSV, EUC-KR도 됨)을 올리면 주문번호로 찾아 한 번에 발송 처리하고 재고를 뺍니다. 못 찾은 주문번호는 미리보기에 따로 보여 줍니다. 송장번호를 표에 직접 적어 처리할 수도 있습니다. ③ **채널에 송장 등록**: 최근 발송분을 채널별로 주문번호·택배사·송장번호 CSV로 받아 판매자센터의 송장 일괄 등록에 올립니다. |
| 상품·재고 | 상품명·옵션·SKU·공급처·판매가·매입가·재고·안전 재고. 옵션마다 따로 등록하면 옵션별 재고를 셉니다. **재고 조정**은 실제 수량으로 맞추거나 더하고 빼며 사유(실사 조정·파손·폐기·증정·샘플 등)를 남깁니다. **기록**에서 발송·반품·입고·조정 내역을 최근 100건까지 봅니다. |
| 발주·입고 | 안전 재고 아래 상품을 공급처별로 묶어 **발주서 만들기**를 제안합니다(안전 재고의 두 배까지 채우는 수량). 발주서를 **저장하고 보내기**를 누르면 공급처에 보낼 메시지와 **확인 링크**가 만들어집니다. 공급처는 계정 없이 링크에서 **발주 내용을 확인했습니다** 또는 **변경을 요청합니다**를 누르고, 결과가 바로 표시됩니다. 물건이 오면 **입고 처리**에서 받은 수량을 적으면 연결된 상품의 재고가 늘어납니다. 전화로 확인받았다면 **확인받은 것으로 표시**를 씁니다. |
| 반품·교환 | **＋ 반품·교환 접수**에서 주문을 찾아 등록하고 접수 → 회수 완료 → 처리 완료로 진행합니다. 반품은 처리 완료 때 주문이 ‘반품’으로 바뀌어 매출에서 빠지고, 교환은 0원짜리 **재발송 주문**이 생겨 송장·발송으로 넘어갑니다. 회수한 상품을 다시 팔 수 있으면 **재입고**에 체크합니다(사유가 불량·파손이면 자동으로 꺼집니다). 주문 화면에서도 바로 접수할 수 있습니다. |
| 문의 | 고객 문의와 답변 기한(기본 다음 날). **자주 쓰는 답변**에서 골라 넣거나, **클로드에게 초안 부탁할 문장 복사**로 초안을 받아 고친 뒤 **답변 완료**로 처리합니다. 복사되는 문장에는 고객 연락처·주소가 들어가지 않습니다. |
| 손익·정산 | 월별·채널별 매출(취소·반품 제외), 채널 수수료(설정의 수수료율), 배송비, 상품 원가(연결된 상품의 매입가 × 수량), 광고비·기타(직접 입력) → 손익. **상품별 손익**(판매 수량·매출·수수료·원가·마진율)과 **정산 대사**(예상 정산액 = 매출 − 수수료, 채널 정산서 금액으로 고칠 수 있음 · 입금액 · 차이)를 함께 봅니다. **이달 손익을 돈에 기록**으로 돈 메뉴에 수입·지출로 넣습니다. |
| 설정 | 판매 방식, 판매 채널(수수료율·정산 주기), 기본 배송비, 기본 택배사, 자주 쓰는 답변, 운영 메모. 기본 채널은 네이버 스마트스토어·쿠팡·자사몰·오프라인이고, 넣어 둔 수수료율은 대략적인 값이라 계약 조건대로 고쳐 두면 손익이 정확해집니다. |

### 발송 담당 화면

현장 근무자로 로그인하면 **오늘 발송**에 신규·포장 주문(교환 재발송 포함)이 카드로 보입니다. 카드를 열어 **포장 완료**, 송장번호·택배사를 적고 **발송 완료**를 누릅니다. 최근 이틀 안에 발송한 주문은 아래에 남아 송장을 고칠 수 있습니다. **금액·매입가·정산·공급처 정보는 발송 담당 기기로 전송되지 않습니다.** 수령인 이름·연락처·주소는 발송 전 주문에만 내려가고, 발송이 끝난 주문은 이름 첫 글자만 보입니다.

## 마이택스 — 숫자와 세금 준비

왼쪽 메뉴 **마이택스**. 관리자·직원이 씁니다. 수입·지출은 **돈** 메뉴의 기록을 그대로 쓰므로 따로 옮겨 적지 않습니다. 마이스토어·마이셀러·거래·마이피플에서 돈으로 보낸 기록도 모두 들어옵니다. 세금 숫자는 모두 **참고용 추정**이고, 신고는 홈택스나 세무사를 통해 합니다.

```
돈 기록 → 사업자별로 나누기 → 손익 구조·흐름·KPI → 증빙 확인·홈택스 자료 대조 → 신고 자료(부가세·종소세) → 세금 달력
```

| 화면 | 내용 |
|---|---|
| 현황 | 이달 매출·영업이익(지난달 같은 기간과 비교), 올해 누적, 지금 현금(시작 잔액을 넣으면), 최근 6개월 막대, 다가오는 세금 일정, KPI, 확인할 것 |
| 손익 | 월별 손익표(매출 → 매출원가 → 매출총이익 → 수수료·인건비·임차료 등 → 영업이익 → 영업외). 항목은 설정의 **손익 구조**에서 정합니다. CSV로 받습니다. |
| 흐름 | 월별 매출과 1년 전 비교, 매출 출처(직접·마이스토어·마이셀러·거래), 앞으로 60일 현금 흐름(받을 청구 대금, 고정 지출·수입, 예상 세금, 급여 포함) |
| KPI | 매출·영업이익·이익률·매출총이익률·지출·특정 항목·직접 입력 지표. 월·분기·연 목표를 세우고 기간별 달성률과 지난 기록을 봅니다. 추천 목표를 누르면 바로 만들어집니다. |
| 신고 자료 | 사업자·기간을 고르면 **부가세**(일반·간이·면세)를 홈택스 신고서 칸 순서로, **종합소득세**를 과세표준·세율·공제까지 추정합니다. 기록마다 증빙 종류·과세 구분·사업자를 고르고, **사업과 무관한 돈만** 사유를 남겨 신고에서 뺍니다(아래 참고). 세무사용 CSV를 받습니다. |
| 증빙 | 세금계산서·계산서·현금영수증·카드 대장. **홈택스 파일 올리기**(엑셀·CSV, 열 이름 자동 인식)와 **돈 기록과 맞추기**(금액·날짜로 자동 연결, 없는 기록은 새로 추가). 거래 메뉴의 청구 중 세금계산서를 아직 발행하지 않은 것을 모아 홈택스 발급에 쓸 내용을 복사합니다. |
| 세금 달력 | 부가세(확정·예정·간이), 종합소득세(중간예납 포함), 원천세(매월·반기), 4대보험, 세금계산서 발급 마감, 지원사업 마감. 주말이면 다음 월요일로 옮깁니다. **휴대폰 일정으로 내보내기**(.ics, 3일 전 알림) |
| 절세·지원 | 노란우산·장부·성실신고·창업감면·적격증빙·사업용 카드·불공제·카드 발행 세액공제 같은 점검표와 예상 효과, 지원사업 모음(직접 추가·기업마당 공고 받기), **세무사에게 보낼 요약 / 클로드에게 물어볼 문장 복사** |
| 설정 | 사업자(개인·법인, 일반·간이·면세, 업종, 연결할 브랜드·매장·확장판), 손익 구조, 현금(시작 잔액·고정 지출), 내 공제 정보(부양가족·노란우산 등), 연결(API 키 상태) |

### 신고에서 빼는 것 — 할 수 있는 것과 없는 것

신고 자료에서 기록을 빼려면 **사유를 반드시 고르고** 메모를 남겨야 합니다. 고를 수 있는 사유는 내 계좌끼리 옮긴 돈, 보증금·예치금, 빌린 돈·대출 원금, 환불·취소 상계, 사업과 무관한 개인 거래처럼 **애초에 사업 매출·경비가 아닌 돈**뿐입니다. 다른 사업자의 돈이라면 빼지 말고 그 기록의 사업자를 바꿉니다. 뺀 기록은 지워지지 않고 사유와 함께 ‘신고에서 뺀 것’ 목록에 남고, 언제든 다시 포함할 수 있습니다.

실제 사업 매출을 빼는 기능은 없습니다. 그렇게 하면 과소신고가 되고 가산세 대상이 됩니다. 특히 카드·현금영수증·세금계산서 매출은 국세청이 이미 알고 있으므로, 이런 매출을 빼려고 하면 경고를 띄우고 다른 사업자의 매출이라면 **사업자만 옮기라고** 안내합니다.

### 국세청·기업마당 연결 (선택)

키를 넣지 않아도 마이택스는 다 쓸 수 있습니다. 넣으면 거래처 사업자 상태 조회와 지원사업 공고 받기가 켜집니다.

1. **국세청 사업자 상태 조회** — [공공데이터포털](https://www.data.go.kr)에서 ‘국세청_사업자등록정보 진위확인 및 상태조회 서비스’를 활용 신청합니다(무료, 보통 바로 승인). 마이페이지의 **일반 인증키(Decoding)** 를 복사합니다.
2. **기업마당 지원사업 공고** — [기업마당](https://www.bizinfo.go.kr) → 정책정보 개방 → API 신청에서 인증키를 받습니다.
3. Cloudflare 대시보드 → **Workers & Pages** → **myworkspro** → **Settings** → **Variables and Secrets** → **Add**. 이름은 각각 `NTS_API_KEY`, `BIZINFO_API_KEY`, 값은 받은 키, **Encrypt**로 저장합니다.
4. **Deployments**에서 최근 배포의 **⋯ → Retry deployment**. 마이택스 → 설정 → 연결에서 ‘연결됨’으로 보이면 끝입니다.

### 홈택스 자동 수집 (선택)

증빙 탭 맨 위의 **홈택스 자동 수집**에서 사업자마다 한 번 이어 두면, 홈택스에 올라온 **전자세금계산서(매출·매입)** 와 **현금영수증(매출·매입)** 이 증빙 대장으로 들어옵니다. 카드 매입 내역은 지금처럼 파일로 올립니다.

홈택스에는 바깥 프로그램이 쓸 수 있는 연결 창구가 없어서, 홈택스 수집 서비스 **팝빌**(㈜링크허브)을 거칩니다.

| 걸음 | 하는 일 |
|---|---|
| ① 수집 서비스에 사업자 등록 | 상호·대표자·주소·업태·종목·담당자 연락처가 팝빌에 전달되어 회원으로 등록됩니다(동의 필요). 팝빌 아이디와 비밀번호는 한 번만 보여 줍니다. |
| ② 홈택스 ‘부서사용자’ 등록 | 부서사용자는 홈택스에서 만드는 **조회 전용 아이디**입니다. 홈택스에 사업자 인증서로 로그인해 메뉴 검색에서 ‘부서사용자’를 찾아 만들고, 전자(세금)계산서와 현금영수증 조회 권한을 줍니다. 대표 아이디나 인증서는 맡기지 않습니다. 비밀번호는 팝빌에 등록하는 데에만 쓰고 마이웍스에는 저장하지 않습니다. |
| ③ 가져오기 | **지금 가져오기** — 처음에는 지난 석 달, 그다음부터는 지난번보다 이레 앞에서부터. **날마다 자동**을 켜면 아침마다 가져오고, 새 증빙이 있으면 알림으로 알려 줍니다. |

- 승인번호가 같은 건은 다시 들어가지 않습니다. 손으로 고친 증빙은 건드리지 않습니다.
- 면세 세금계산서는 ‘계산서’로, 취소된 현금영수증은 음수 금액으로 들어옵니다.
- 가져온 뒤 **돈 기록과 맞추기**를 누르면 금액·날짜가 맞는 기록과 이어집니다.
- **연결 끊기**를 누르거나 워크스페이스를 지우면 팝빌에 등록해 둔 부서사용자 정보도 함께 지웁니다. 이미 가져온 증빙은 남습니다. 팝빌 회원 탈퇴는 팝빌에 따로 요청합니다.
- **운영자 준비**: 팝빌과 연동 계약을 맺고 받은 값을 Cloudflare 비밀값 `POPBILL_LINK_ID`, `POPBILL_SECRET_KEY`로 넣습니다. 시험 환경으로 먼저 확인하려면 `POPBILL_TEST`에 `1`을 넣습니다. 이용 요금은 팝빌 정책(정액제)을 따릅니다. 값을 넣기 전에는 카드에 ‘준비 중’으로만 보입니다.

홈택스에 직접 로그인해 세금계산서를 자동 발행하거나 신고서를 제출하는 기능은 넣지 않았습니다. 홈택스는 개인 프로그램의 자동 로그인을 허용하지 않고, 자동 발행은 국세청에 등록된 전자세금계산서 발급 대행(ASP) 업체와 계약해야 합니다. 대신 홈택스에서 받은 파일을 올려 맞추고, 발급할 내용을 복사해 홈택스에 붙여 넣는 방식으로 일을 줄였습니다.

## 마이피플 — 함께 일하는 사람과 근무·급여

확장판 **마이피플**을 켜면 왼쪽 메뉴 **사람**이 **마이피플**로 바뀌고, 구성원·연락처 탭 옆에 한눈에·고용·근무자·근무표·출퇴근·급여(관리자만) 탭이 생깁니다. 현장 근무자와 시설 담당에게는 **내 근무** 메뉴가 생깁니다.

| 화면 | 내용 |
|---|---|
| 연락처·파트너 | 연락처를 누르면 파트너 카드가 열립니다. 별점, ‘다시 함께할지’, 단가·조건 메모, 주의할 점, 협업 이력, 마이웍스 프로젝트·거래 기록, **레퍼런스 체크**(물어볼 질문 복사 → 들은 답과 추천도 기록), **명함 사진**. 연락처 추가 화면의 **명함 글자로 채우기**에 휴대폰 ‘텍스트 인식’으로 복사한 명함 글을 붙이면 이름·회사·직함·연락처를 채웁니다. **고용 인력으로 등록**으로 바로 근무자가 됩니다. |
| 한눈에 | 오늘 근무·출근 기록 없음·이번 주 근무 시간·서류 확인, 지난달 급여 지급 상태, 믿을 만한 파트너 |
| 고용·근무자 | 아르바이트·직원·건당·일용직·프리랜서. 급여 방식(시급·일급·주급·월급·건당)과 공제 방식(4대보험·3.3%·일용직·없음), 근무 요일, 근무 매장, 마이웍스 계정 연결, 근로계약서·보건증·4대보험 취득 날짜. **근로계약서 인쇄** |
| 근무표 | 주 단위 표. 칸을 눌러 근무를 넣고(근무 요일 한 번에 넣기), 근무를 눌러 고칩니다. **지난주 근무표 복사** |
| 출퇴근 | 날짜별 예정·출근·퇴근·근무 시간과 지각·일찍 퇴근·기록 없음·퇴근 안 찍음·매장과의 거리 표시. 관리자가 넣거나 고칠 수 있고 기록이 남습니다. 건당 근무 기록, 매장 출근 위치 등록 |
| 급여 | 월별로 근무자마다 자동 계산 → 저장 → 확정 → **명세서 링크 보내기** → **지급 완료**(돈 메뉴에 인건비로 기록). 급여 대장 CSV, 계산 기준(5인 이상 여부, 급여일, 4대보험·산재 요율) |

급여 계산 기준(2026년, 설정에서 고칠 수 있음): 최저임금 시간당 10,320원. 주 15시간 이상 근무한 주는 주휴수당((주 근무시간 ÷ 40) × 8시간, 최대 8시간). 5인 이상 사업장은 하루 8시간·주 40시간을 넘는 시간과 밤 10시~아침 6시에 50% 가산. 4대보험 근로자 부담은 국민연금 4.75%, 건강보험 3.595%, 장기요양 건강보험료의 13.14%, 고용보험 0.9%. 근로소득세는 간이세액표 금액을 근무자 정보에 적어 두면 그대로 씁니다. 3.3%는 사업소득세 3%와 지방소득세 0.3%, 일용직은 (일당 − 15만 원) × 6% × 45%이고 1천 원 미만은 떼지 않습니다. 모두 참고값이니 지급 전에 확인하세요.

- **급여·시급·계좌·생년월일은 워크스페이스 관리자만 봅니다.** 직원 역할은 근무표·출퇴근은 관리하지만 금액은 받지 않고, 근무자 본인은 자기 근무표·출퇴근·명세서만 봅니다.
- 근무자는 **내 근무**에서 출근·퇴근을 누릅니다. 휴대폰이 위치를 알려 주면 매장과의 거리만 남깁니다.
- 임금명세서 링크는 계정 없이 열리고, 근무자가 **명세서를 받았습니다** 또는 **문의합니다**를 누르면 급여 화면에 표시됩니다.

## 마이마케팅 — 광고·홍보 운영

왼쪽 메뉴 **마이마케팅**. 관리자·직원이 씁니다. 검색광고·타겟광고·콘텐츠·영상·체험단·메시지·오프라인을 채널이 달라도 같은 눈금(광고비·노출·클릭·전환·매출)으로 모아 보고, 무엇을 고칠지와 예산을 어떻게 옮길지 알려 줍니다. 광고 계정의 예산·입찰·소재를 대신 바꾸지는 않습니다. 바꿀 내용을 숫자로 적어 주고, 바꾼 뒤의 효과를 다시 잽니다.

```
채널·캠페인 → 성과 모으기(보고서 파일 · 연결 · 직접 입력) → 현황·성과 → 최적화(고칠 것 · 설정 점검표) → 부스터(실행안 → 했어요 → 효과) → 돈 메뉴
```

| 화면 | 내용 |
|---|---|
| 현황 | 이달 광고비(월 예산 대비)·전환·클릭·ROAS, 매출 대비 광고비(돈 메뉴의 이달 수입 기준), 최근 14일 막대, 채널별 표, **지금 할 일**(실행안·고칠 것), **목표 대비**(예산 사용, 전환당 비용, ROAS, 전환 수, 설정 점검), 이번 주 콘텐츠. 맨 위에서 모드를 고릅니다. |
| 캠페인 | 분류(검색광고·타겟광고·콘텐츠·영상·체험단·인플루언서·메시지·지역·오프라인)·상태·채널로 거르고, 카드마다 어제까지 7일 광고비·클릭·전환·전환당 비용을 봅니다. 캠페인을 누르면 기간별 표, 소재·키워드별 성과, 날짜별 기록, 고칠 것이 나옵니다. 목표(문의·예약 / 구매 / 매장 방문 / 방문 늘리기 / 알리기 / 다시 오게), 예산(하루·한 달·기간 전체), 목표 전환당 비용·목표 ROAS, 도착 페이지, 모드를 캠페인마다 정합니다. |
| 성과 | 기간(7·14·30·90일, 이번 달, 지난달)과 채널을 고르고 채널·분류·캠페인·날짜로 나눠 봅니다. 노출 → 클릭 → 전환 → 매출 흐름과 앞 기간 대비 변화, 기록 목록(지우기), CSV. **광고비를 돈에 기록**을 누르면 그 달 광고비가 채널마다 지출 한 줄로 돈 메뉴에 들어가고, 다시 누르면 금액만 고칩니다. |
| 콘텐츠 | 월 달력에 글을 잡고(아이디어 → 작성 중 → 게시 준비 → 게시함), 올린 뒤 조회·반응 수를 적어 무엇이 통했는지 남깁니다. **아이디어 받기**는 업종에 맞는 주제 12개를 보여 줍니다. 협찬·체험단 글에 체크하면 표시 규정을 알려 줍니다. 글마다 **클로드에게 초안 부탁할 문장 복사**가 있습니다. |
| 키워드 | 쓰는 중·지켜보는 중·제외로 나눠 관리합니다. 여러 줄 붙여 넣기, 앞말×뒷말 **조합기**, CSV. 네이버 검색광고를 연결하면 **연관 키워드 찾기**(한 달 검색 수·경쟁 정도)가, 운영자가 데이터랩 키를 넣으면 **검색 관심도 추이**가 켜집니다. |
| 최적화 | **고칠 것** — 캠페인마다 기록을 보고 문제와 고치는 순서를 짚습니다. **설정 점검표** — 쓰는 채널에 맞춰 네이버 파워링크·쇼핑검색·플레이스·블로그, 메타 광고, 인스타그램, 유튜브, 구글, 카카오, 당근, 체험단, 문자·알림톡 등의 설정 항목과 이유를 보여 주고 체크합니다. **링크 꼬리표(UTM) 만들기**. |
| 부스터 | 목표 전환당 비용·목표 ROAS·월 예산 사용, **지금 할 일**(실행안마다 지금 값 → 바꾼 뒤 값과 근거, 했어요·업무로 보내기·건너뛰기), **예산 판단** 표(목표 대비 효율과 늘리기·그대로·줄이기·멈춤), **한 일과 효과**. |
| 설정 | 사업·목표(업종, 객단가, 마진율, 월 예산, 목표), 채널, 연결(광고 계정), 판단 기준(보는 기간, 한 번에 바꾸는 폭, 필요한 클릭·노출·전환 수, 점검 기준). 기획 마법사와 클로드 연동도 여기서 엽니다. |

### 모드 세 가지

| 모드 | 하는 일 |
|---|---|
| 기본 | 기록하고 봅니다. |
| 최적화 | 무엇을 고칠지 짚어 주고 설정을 안내합니다. 현황과 홈 화면에 고칠 것이 나타납니다. |
| 부스터 | 최적화에 더해, 목표에 맞춰 예산·입찰·소재를 얼마나 바꿀지 숫자로 냅니다. 화면을 열 때마다 새 실행안을 **지금 할 일**에 넣어 둡니다(같은 실행안은 한 주에 한 번). |

현황 맨 위에서 고른 모드가 기본값이고, 캠페인 수정에서 캠페인마다 다르게 둘 수 있습니다. 부스터는 전환이 기록되는 캠페인에서만 뜻이 있으므로, 먼저 최적화 탭의 측정 점검을 마쳐 두세요.

### 성과를 넣는 세 가지 방법

1. **보고서 파일 올리기** — 네이버·메타·구글·카카오 광고 관리자에서 내려받은 보고서(엑셀·CSV, EUC-KR도 됨)를 그대로 올립니다. 열 이름을 보고 날짜·캠페인·상세(소재·광고그룹·키워드)·광고비·노출·클릭·전환·매출을 맞추고, 틀리면 화면에서 고칩니다. 머리말 줄과 합계 줄은 건너뜁니다. 목록에 없는 캠페인은 새로 만듭니다. 날짜 열이 없는 기간 합계 보고서는 고른 날짜 하루에 넣습니다. 파일은 브라우저에서만 읽고 고른 열의 숫자만 저장합니다.
2. **광고 계정 연결** (선택) — 네이버 검색광고와 메타 광고는 연결해 두면 화면을 열 때(여섯 시간에 한 번) 최근 14일을 가져옵니다. 유튜브 채널은 구독자·조회 수를 날마다 남깁니다.
3. **성과 적기** — 전화·방문 문의처럼 추적되지 않는 전환, 인스타그램 계정의 조회·반응·팔로워처럼 파일이 없는 숫자를 직접 적습니다.

성과는 **날짜 × 채널 × 캠페인** 한 칸 단위로 들어갑니다. 같은 칸을 다시 올리거나 가져오면 그 칸을 통째로 바꾸므로, 같은 파일을 두 번 올려도 두 번 세지 않습니다. 상세 줄이 있는 칸에 합계 한 줄을 직접 적으려 하면 바꿀지 먼저 묻습니다.

### 최적화가 짚는 것

어제까지의 기록을 봅니다(오늘 숫자는 덜 찼기 때문). 클릭·노출이 기준 수보다 적은 캠페인은 판단하지 않습니다.

| 고칠 것 | 언제 |
|---|---|
| 전환이 한 건도 기록되지 않았습니다 | 30일 동안 클릭을 50번 이상 받고 전환 0건 → 전환 추적부터 확인 |
| 클릭률이 낮습니다 | 최근 7일 클릭률이 점검 기준보다 낮을 때. 점검 기준의 두 배 안쪽이면서 같은 분류의 내 다른 캠페인(둘 이상) 평균의 절반에 못 미칠 때도 |
| 소재가 지쳤습니다 | 타겟·영상 광고의 클릭률이 지난 7일보다 30% 이상 떨어짐 |
| 클릭 단가가 높습니다 | 지난 7일보다 30% 넘게 오르거나, 같은 분류의 내 다른 캠페인(둘 이상) 평균의 두 배를 넘음 |
| 클릭은 오는데 전환이 적습니다 | 14일 클릭이 100번 이상이고 전환이 있는데 전환율이 점검 기준 아래 → 도착 페이지 점검 |
| 전환 한 건이 목표보다 비쌉니다 · ROAS가 목표에 못 미칩니다 | 14일 전환당 비용이 목표의 120% 초과(전환 3건 이상) / ROAS가 목표의 80% 미만 |
| 하루 예산에 걸립니다 · 예산을 다 못 씁니다 | 7일 가운데 5일 이상 하루 예산 소진 / 예산의 절반도 못 씀 |
| 최근 기록이 없습니다 · 기간이 끝났습니다 · 도착 페이지가 비었습니다 | 진행 중인데 7일 동안 기록 없음 등 |
| 콘텐츠가 끊겼습니다 | 콘텐츠 채널에 2주 넘게 게시가 없고 이레 안에 잡힌 글도 없음 |

점검 기준(클릭률·전환율)은 **참고값**입니다. 업종과 상품에 따라 크게 다르므로 설정 → 판단 기준에서 고쳐 쓰세요.

### 부스터가 내는 실행안

목표는 캠페인의 목표 전환당 비용(또는 목표 ROAS) → 설정의 목표 → **손익분기**(전환당 비용 = 객단가 × 마진율, ROAS = 100 ÷ 마진율) 순으로 씁니다. 목표 대비 효율은 `목표 전환당 비용 ÷ 실제 전환당 비용`(구매 목표이고 매출이 기록되면 `실제 ROAS ÷ 목표 ROAS`)이고, 어제까지 14일을 봅니다.

| 실행안 | 조건 |
|---|---|
| 멈추고 원인 확인 | 클릭은 30번 넘게 받았는데 전환 없이 목표 전환당 비용의 2배를 씀 |
| 예산 옮기기 | 늘릴 캠페인과 줄일 캠페인이 함께 있을 때 — 작은 쪽 하루 예산의 20%를 옮김 |
| 예산 늘리기 · 줄이기 | 전환이 3건 이상 모인 캠페인의 효율이 110% 이상 / 75% 미만 — 한 번에 20% |
| 소재·키워드 겨루기 | 상세 줄이 둘 이상이고 클릭이 충분할 때, 못하는 쪽을 끄고 잘하는 쪽에 모음 |
| 소재 3개 이상으로 | 타겟·영상 광고에 도는 소재가 1~2개일 때 |
| 지켜보는 키워드 넣어 보기 | 검색량이 있고 경쟁이 세지 않은 후보가 둘 이상일 때 |
| 자동화 상품 나란히 시험 | 30일 전환이 30건 이상인 메타(어드밴티지+)·네이버 쇼핑·플레이스·GFA(애드부스트)·구글(실적 최대화) 캠페인 |
| 월 예산 속도 | 7일 이후, 이대로면 월 예산을 10% 넘게 넘기거나, 30% 넘게 남는데 늘릴 캠페인이 있을 때 |

비율과 기준 수(20%, 클릭 30번, 전환 3건, 보는 기간 7일)는 설정 → 판단 기준에서 바꿉니다. 실행안을 광고 관리자에서 실제로 바꾼 뒤 **했어요**를 누르면, 그날 앞뒤 같은 기간의 전환당 비용(또는 ROAS·클릭당 비용)을 견줘 **한 일과 효과**에 보여 줍니다. **업무로 보내기**는 업무보드에 업무를 만들고 담당·마감을 붙입니다.

### 기획 받기

- **기획 마법사** — 업종·목표·월 예산·객단가·마진율·가진 것(스마트플레이스, 인스타그램 등)·키워드 앞말·뒷말을 넣으면, 채널별 예산 배분(고칠 수 있음), 목표 숫자(손익분기와 이익 30%를 남기는 선), 캠페인(준비 상태), 처음 할 일, 4주 콘텐츠(주 2회), 키워드를 한 번에 만듭니다. 한 달 30만 원 아래면 채널을 두 곳으로 모읍니다. 배분은 시작안이고, 2주 돌려 본 뒤 성과대로 옮기는 것을 전제로 합니다.
- **클로드에게 맡기기** — 사업 정보와 최근 30일 성과를 담은 문장을 복사해 클로드에 붙여 넣으면 `myworks-marketing/v1` 형식의 기획 파일을 받습니다. 설정 → **기획 파일 가져오기**에 붙여 넣으면 미리 본 뒤 만듭니다. 고객 이름·연락처는 문장에 들어가지 않습니다.
- **클로드 직접 연결** — AI 접속 토큰에 마이마케팅을 고르면 클로드가 `myworks_marketing`으로 성과를 읽고, `mk-action`(실행안)·`mk-post`(콘텐츠 초안)를 제안합니다. 제안은 홈의 **오늘 결정할 것**에서 승인해야 들어옵니다.

### 광고 계정 연결 (선택)

연결하지 않아도 보고서 파일 올리기로 모든 기능을 씁니다. 연결 정보는 암호화해 보관하고 화면으로 다시 보내지 않으며, 백업 파일에도 넣지 않습니다. 성과를 읽기만 합니다.

**운영자가 먼저 할 일** — Cloudflare → Workers & Pages → myworkspro → Settings → Variables and Secrets → Add에서 아래 이름으로 값을 넣고 Encrypt로 저장한 뒤 Deployments에서 Retry deployment.

| 이름 | 쓰임 |
|---|---|
| `MW_VAULT_KEY` | 광고 계정 연결 정보를 암호화하는 키. 16자 이상 아무 문자열. 없으면 연결 버튼이 잠깁니다. 바꾸면 기존 연결을 다시 해야 합니다. |
| `YT_API_KEY` | 유튜브 채널 구독자·조회 수 (구글 클라우드 콘솔에서 YouTube Data API v3 키) |
| `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` | 검색 관심도 추이 (네이버 개발자센터에서 애플리케이션 등록 → 데이터랩 검색어트렌드). 워크스페이스마다 하루 40번까지 |

**워크스페이스 관리자가 할 일** — 마이마케팅 → 설정 → 연결.

- **네이버 검색광고** — 네이버 검색광고 → 도구 → API 사용 관리에서 액세스라이선스와 비밀키를 발급받고, 같은 화면의 고객 ID(CUSTOMER_ID)와 함께 넣습니다. 캠페인별 노출·클릭·광고비(부가세 포함)·전환·전환 매출을 날짜별로 가져오고, 연관 키워드 찾기가 켜집니다. 캠페인 30개까지.
- **메타 광고** — 메타 비즈니스 설정 → 시스템 사용자에서 광고 계정을 읽을 수 있는(ads_read) 토큰을 만들고 광고 계정 ID(act_ 뒤 숫자)와 함께 넣습니다. 캠페인별 노출·링크 클릭·지출·전환을 날짜별로 가져옵니다. 전환으로 셀 것(구매 / 잠재 고객 / 메시지 대화)은 연결 화면에서 고릅니다.
- **유튜브** — 채널에 ‘유튜브 채널’을 등록하고 핸들(@이름)을 적습니다.

구글 광고·카카오모먼트·당근·틱톡과 인스타그램 계정 통계는 보고서 파일로 넣습니다(구글·카카오는 개발자 토큰이나 심사가 필요합니다). 광고 계정에 **쓰는** 기능(예산·입찰 자동 변경, 소재 등록)은 넣지 않았습니다. 잘못 바뀌면 바로 돈이 나가는 일이라, 실제 계정으로 충분히 확인한 뒤에 여는 것이 맞습니다.

### 숫자 읽는 법

- 클릭률 = 클릭 ÷ 노출 · 전환율 = 전환 ÷ 클릭 · 전환당 비용(CPA) = 광고비 ÷ 전환 · ROAS = 광고 매출 ÷ 광고비.
- 여러 캠페인을 묶은 ROAS는 **매출을 기록한 캠페인의 광고비만** 분모로 씁니다. 매출을 재지 않는 광고비까지 넣으면 실제보다 낮게 나옵니다.
- 네이버 검색광고에서 가져온 광고비는 부가세가 든 금액입니다. 파일로 올린 금액은 파일에 적힌 그대로입니다.
- 손익분기와 점검 기준은 참고값입니다. 재방문이 많은 사업은 첫 구매에서 본전보다 더 써도 됩니다.

## 마이크리에이터 — 협찬·콘텐츠·수익

왼쪽 메뉴 **마이크리에이터**. 관리자·직원이 씁니다. 유튜브·인스타그램·블로그 같은 채널을 운영하면서 협찬 제안을 받고, 콘텐츠를 만들고, 여러 곳에서 돈이 들어오는 사람을 위한 확장판입니다. 협찬 한 건이 문의에서 입금까지 가는 길을 한 줄로 챙깁니다. 유튜브·인스타그램 계정과 직접 연결하지는 않고, 구독자와 조회수는 플랫폼 통계를 보고 달마다 적습니다.

```
채널(구독자·조회수) → 협찬 건(문의 → 협의 → 계약 → 제작 → 검수 → 게시 → 정산 대기 → 완료) → 입금 확인 → 수익 → 돈 메뉴
                         ↑ 미디어킷 문의            ↓ 조건 확인서 · 결과 보고서 (브랜드에게 링크로)
```

| 화면 | 내용 |
|---|---|
| 요약 | 이달 수익(세금 전)과 실제 입금, 받을 돈, 진행 중인 협찬, 구독자·팔로워 합계. **챙길 것**(새 문의, 브랜드의 수정 요청, 초안·게시 마감, 입금 지연, 광고 표기 미점검, 게시 임박인데 편집 중인 콘텐츠, 2차 활용·게시 유지 기한), 협찬 흐름, 이레 안 일정, 최근 6개월 수익. |
| 협찬 | 단계별 **보드**와 목록. 건마다 브랜드·대행사·담당자, 종류(유료 광고·제품 협찬·제휴 수수료·공동구매·출연·2차 활용), 금액과 세금 처리, 만들 것, 초안·게시·입금 날짜, 수정 횟수, 2차 활용·독점·게시 유지 조건, 브랜드 요구 사항을 적습니다. 건을 열면 단계를 옮기고, **조건 확인서**와 **결과 보고서** 링크를 만들고, **입금 확인**을 합니다. |
| 콘텐츠 | 아이디어 → 기획 → 촬영 → 편집 → 검수 → 예약 → 게시. **보드**와 **달력**으로 보고, 협찬 건과 연결하고, 편집을 맡긴 사람과 외주비, 올리기 전 점검(썸네일·제목·자막·광고 표기 등 9가지), 게시 주소와 조회·좋아요·댓글·공유·저장을 남깁니다. **아이디어 여러 개**는 한 줄에 하나씩 적어 한 번에 담습니다. |
| 수익 | 달마다 어디서 벌었는지(플랫폼 광고수익·협찬·제휴 수수료·후원·판매·강의·2차 활용), 실제 입금, 미리 뗀 세금(원천징수), 올해 협찬 비중. 12개월 흐름, **받을 돈** 목록, 기록 표와 CSV. 해외 수익은 외화 금액과 환율을 적으면 원화로 바뀝니다. **돈에 기록**을 누르면 그 달 수익이 돈 메뉴에 수입으로 들어갑니다. |
| 채널 | 채널마다 구독자·팔로워(달마다 한 번 적음), 그달 조회수와 올린 수, 흐름 선, 최근 90일 콘텐츠의 평균 조회, 조회 1,000회당 광고수익. |
| 단가·견적 | **견적 계산** — 단가표 항목이나 예상 조회수 × 조회당 단가에 2차 활용·독점·급한 일정을 더하고, 세금 뒤 받을 돈까지 보여 줍니다. 문구 복사, 그 금액으로 협찬 건 만들기. **내 실제 단가** — 지난 12개월에 돈을 받은 협찬의 금액 ÷ 결과 조회수. **단가표**와 제안 성사 현황(무산 사유). |
| 미디어킷 | 브랜드에게 보여 주는 내 소개 페이지. 소개·주제·보는 사람·대표 콘텐츠를 고르고 **미디어킷 열기**를 누르면 주소가 생깁니다. 몇 번 열렸는지 보이고, 닫거나 새 주소로 바꿀 수 있습니다. |
| 설정·안내 | 사업 형태(사업자 없음·면세사업자·과세사업자)와 원천징수율, 보내는 사람 정보, 견적에 더하는 비율. 광고 표기, 계약 전에 확인할 것, 세금 안내. |

### 브랜드에게 보내는 링크 세 가지

세 가지 모두 받는 사람은 가입 없이 엽니다. 메모와 다른 브랜드와의 조건은 어디에도 나가지 않습니다.

| 링크 | 무엇을 보여 주나 | 받는 사람이 하는 일 |
|---|---|---|
| **조건 확인서** | 종류, 채널, 만들 것, 금액과 세금, 초안·게시·입금 날짜, 수정 횟수, 2차 활용·독점·게시 유지 조건, 요구 사항, 광고 표기 방식 | **조건을 확인했습니다** 또는 **수정을 요청합니다**. 확인하면 그때의 조건이 날짜·이름과 함께 남고 단계가 ‘계약’으로 넘어갑니다. 수정 요청이 오면 조건을 고쳐 저장하고, 브랜드는 같은 링크에서 다시 확인합니다. 30일 |
| **결과 보고서** | 게시 주소, 조회·좋아요·댓글·공유·저장·링크 클릭, 콘텐츠별 숫자, 한마디. 금액은 나가지 않습니다 | 보기만 합니다. 90일 |
| **미디어킷** | 소개, 채널별 구독자·월 조회(최근 석 달 평균)·콘텐츠 평균 조회, 보는 사람, 대표 콘텐츠, 함께한 브랜드(보여 주기로 한 건만), 단가표(켰을 때만) | **협업 문의**를 남깁니다. 문의는 협찬 보드의 ‘문의’ 칸에 새 건으로 들어오고 홈과 탭에 표시됩니다. 워크스페이스마다 하루 40건까지 받습니다. 1년 |

- 조건 확인서는 계약서를 대신하지 않습니다. 금액이 큰 건은 계약서도 함께 쓰세요.
- 확인받은 뒤에 금액·게시일·만들 것을 바꾸면 건 화면에 **다시 확인받기**가 나옵니다.
- 숫자를 하나도 적지 않은 채널은 미디어킷에 나가지 않습니다.

### 돈 계산

- **금액은 세금 전(공급가)** 으로 적습니다. 세금 처리는 건마다 고릅니다 — 세금계산서(부가세 10%를 더해 받음), 원천징수(설정한 비율만큼 떼고 받음, 기본 3.3%), 세금 계산 없음. 새 건의 기본값은 설정의 사업 형태를 따릅니다.
- **입금 확인**을 누르면 수익 탭에 한 줄이 생기고, 게시를 마친 건은 ‘완료’로 넘어갑니다. 계약금처럼 게시 전에 받은 돈은 단계를 그대로 둡니다. 입금 확인을 취소하면 수익 기록도 함께 지워집니다.
- **돈에 기록**은 줄마다 한 번만 들어갑니다. 다시 누르면 달라진 금액만 고칩니다. 돈 메뉴에는 실제 입금액이 들어가고, 원천징수한 건은 증빙이 ‘원천징수’로, 부가세를 받은 건은 ‘세금계산서’로 표시됩니다. 게시한 콘텐츠의 외주비도 지출로 함께 보냅니다. 마이택스를 켜 두면 사업자 설정에서 ‘마이크리에이터 수익’을 어느 사업자의 돈으로 볼지 고를 수 있습니다.
- **내 실제 단가**는 지어낸 시세가 아니라 내 기록입니다. 돈을 받은 협찬 가운데 결과 조회수를 적은 건으로만 계산하고, 건수가 적을 때는 참고만 하라고 적어 둡니다.
- 세금 계산과 세금 안내는 참고용입니다. 실제 신고는 세무사나 국세청 안내를 따르세요.

### 광고 표기

돈이나 제품을 받고 만든 콘텐츠에는 ‘광고’·‘협찬’ 표시가 들어가야 합니다. 건이 계약 단계를 넘으면 건 화면에 그 채널에 맞는 표기 자리(영상·사진·글·라이브)와 점검 네 가지가 나오고, 검수·게시 단계인데 점검하지 않았으면 **챙길 것**에 올라옵니다. 적어 둔 표기 방식은 조건 확인서와 결과 보고서에 함께 나갑니다. 안내는 공정거래위원회 「추천·보증 등에 관한 표시·광고 심사지침」을 간추린 참고용입니다.

### 클로드와 함께 쓰기

AI 접속 토큰에 마이크리에이터를 고르면 클로드가 `myworks_creator`로 채널 숫자, 진행 중인 협찬, 챙길 것, 독점 조건, 예정 콘텐츠, 최근 게시물 성과, 이달·지난달 수익을 읽습니다. 쓰기 토큰은 `cr-idea`(콘텐츠 아이디어)와 `cr-deal`(협찬 건)을 제안하고, 홈의 **오늘 결정할 것**에서 승인하면 아이디어 칸과 협의 칸에 들어갑니다.

## 알림 — 알림함과 휴대폰 푸시

왼쪽 **알림**(휴대폰은 위쪽 종). 일이 생기면 받는 사람의 알림함에 쌓이고, 푸시를 켠 기기로도 갑니다.

| 종류 | 언제 |
|---|---|
| 회신·문의 | 견적 승인·수정 요청, 납품 확인, 청구서 확인·문의, 발주서 회신, 임금명세서 확인, 협찬 조건 확인, 미디어킷 문의 |
| 업무 | 다른 사람이 나에게 업무를 맡겼을 때, 내 프로젝트의 업무가 ‘검토’로 넘어왔을 때, 프로젝트·매장에 의견이 달렸을 때 |
| 마감 | 내 업무 마감 전날 오후 5시 |
| 돈·세금 | 입금 기한·견적 유효기간 전날, 세금 일정 3일 전과 당일(마이택스), 자동 안내 발송 결과, 홈택스 새 증빙 |
| 사람 | 참여 요청, 초대 수락 |
| AI 제안 | 클로드가 제안을 올렸을 때 (잇달아 올려도 15분에 한 번) |
| 매장·현장 | 청소 배정, 다시 확인 요청, 시설 문제 접수 |
| 아침 요약 | 하루 한 번(기본 8시 30분) — 오늘 마감·지연·챙길 것. 없는 날은 보내지 않습니다 |

- **휴대폰 푸시**는 기기마다 켭니다: 알림 → 알림 설정 → **켜기**. 아이폰·아이패드는 사파리의 공유 → **홈 화면에 추가**로 설치한 마이웍스에서 켭니다(iOS 16.4 이상). 안드로이드·PC는 크롬·엣지·삼성 인터넷에서 바로 켭니다.
- **알림 설정**: 받을 종류, 방해 금지 시간(기본 밤 10시~아침 8시), 아침 요약 시각. 끈 종류와 방해 금지 시간의 알림도 알림함에는 쌓입니다.
- 마감·입금 기한·세금 일정처럼 **때가 정해진 알림**은 앱을 쓰는 동안 앞으로의 것을 서버에 맡겨 두므로, 앱을 닫아 두어도 옵니다.
- 푸시 내용은 기기에서만 풀 수 있게 암호화해 보냅니다(표준 웹 푸시). 로그아웃하면 그 기기로는 더 보내지 않습니다. 비밀번호를 바꾸거나 관리자가 계정을 끄면 등록해 둔 기기가 모두 지워지고, 30일 동안 마이웍스를 열지 않은 기기로도 보내지 않습니다(다시 열면 이어집니다).
- **운영자**: 총괄관리 → 가입·베타 → **기능 열기**에서 ‘휴대폰 푸시 알림’을 켜야 사용자가 기기를 등록할 수 있습니다. 꺼 두어도 알림함은 씁니다.

때가 정해진 알림과 자동 작업은 누군가 앱을 쓰고 있으면 5분에 한 번 처리됩니다. 아무도 쓰지 않는 시간에도 제때 가도록, 저장소의 `.github/workflows/tick.yml`이 15분마다 `/api/tick`을 부릅니다. GitHub은 저장소에 60일 동안 변화가 없으면 예약 실행을 멈추고 메일로 알려 줍니다. 그때는 저장소의 Actions 탭에서 **tick**을 다시 켜면 됩니다.

## 문자·알림톡 — 고객에게 바로 보내기

연동·데이터 → **문자·알림톡**. 관리자·직원이 씁니다. 워크스페이스마다 **자기 솔라피(SOLAPI) 계정**을 연결해 보냅니다. 요금은 솔라피에 직접 내고, 마이웍스가 따로 받는 돈은 없습니다.

1. 솔라피에 가입하고 충전합니다.
2. 솔라피에서 발신번호를 등록합니다(휴대폰 인증). 등록하지 않은 번호로는 보낼 수 없습니다.
3. 솔라피에서 API 키를 만들어 **연결·문구** 탭에 붙여 넣습니다. 키에 허용 IP를 걸어 두면 연결되지 않습니다.

| 탭 | 내용 |
|---|---|
| 보내기 | 연락처에서 고르거나 번호를 적어 한 번에 50명까지. `{이름}`은 받는 사람 이름으로 바뀝니다 |
| 보낸 기록 | 받는 사람, 내용, 종류(문자·긴 문자·알림톡), 접수 결과, 자동 여부. 보낸 지 1년이 지난 기록은 지워집니다 |
| 자동 안내 | 입금 기한 전·기한 지남, 견적 회신 요청, 예약 전날 이용 안내(마이스토어). 기본은 모두 꺼짐 |
| 연결·문구 | 보내는 번호, 문자 앞 이름, 하루 한도(기본 300건), 용도별 문구, 알림톡 템플릿 연결 |

- **링크를 만드는 창마다 ‘문자·알림톡’ 버튼**이 있습니다 — 견적·청구서·납품 확인 링크, 발주서, 임금명세서, 협찬 조건 확인서, 초대, 진행 상황 공유. 받는 사람과 문구가 채워져 있고, 보내기 전에 고칠 수 있습니다.
- **알림톡**은 카카오 심사를 받은 템플릿으로만 보낼 수 있습니다. 솔라피에서 채널을 연결하고 템플릿을 등록한 뒤, 용도에 이어 주면 그 용도는 알림톡으로 나가고 받지 못하면 문자로 갑니다. 템플릿에 `#{이름}` `#{제목}` `#{금액}` `#{기한}` `#{코드}`처럼 같은 이름을 쓰면 자동으로 이어집니다. 링크 버튼은 `https://myworks.ai.kr/link/#{코드}`로 등록합니다.
- **자동 안내**는 오전 9시~오후 8시 사이에만 보내고, 보내기 직전에 상태를 다시 확인합니다(그 사이 입금됐으면 보내지 않음). 같은 안내는 한 번만 갑니다. 보내는 도중 연결이 끊겨 접수됐는지 알 수 없으면 ‘확인 필요’로 남기고 다시 보내지 않으며, 받는 쪽에서 거절한 안내는 두 번까지만 시도합니다. 고객 연락처에 휴대폰 번호가 있어야 합니다.
- **거래와 관련된 안내만** 보냅니다. `(광고)`로 시작하는 문자는 받지 않습니다. 광고 문자는 수신 동의, 표기, 야간 제한 같은 규정이 따로 있어 이 기능의 범위 밖입니다.
- API 키는 암호화해 보관하고 화면에 다시 보여 주지 않습니다. 백업 파일에도 들어가지 않습니다.
- **운영자 준비**: 연결 정보를 암호화하는 Cloudflare 비밀값 `MW_VAULT_KEY`(16자 이상)가 있어야 열립니다. 마이마케팅의 광고 계정 연결과 같은 값입니다.

## 확인 링크 — 계정 없는 상대에게 보내기

견적서·청구서·납품물·발주서는 **확인 링크**(`사이트주소/app/#/link/…`, 짧게는 `사이트주소/link/…`)로 보냅니다. 받은 사람은 로그인 없이 내용을 보고 **승인 / 확인 / 수정 요청**만 할 수 있습니다.

- 링크는 30일(견적은 만들 때 정한 기간) 동안 유효하고, 같은 대상으로 새 링크를 만들면 이전 링크는 닫힙니다.
- 상대가 누른 결과는 보낸 사람의 마이웍스에 바로 기록되고(활동 기록, 홈의 결정할 것), 수정 요청 사유도 함께 들어옵니다.
- 수정 요청이 온 견적은 고친 뒤 같은 링크로 다시 승인받을 수 있습니다. 납품 확인도 담당자가 다시 검수 요청하면 같은 링크로 다시 답할 수 있습니다.
- 링크 페이지에는 고객의 연락처, 내부 메모, 다른 업무 정보가 나가지 않습니다.

### 진행 상황 공유

프로젝트 화면의 **진행 상황 공유**로 읽기 전용 링크를 만듭니다. 받은 사람은 로그인 없이 진행률, 시작·마감일, 목표, 업무 목록(제목·상태·마감일)을 봅니다. 업무 목록은 빼고 진행률만 보여 줄 수도 있습니다. 예산·메모·의견·담당자 이름은 나가지 않습니다. 몇 번 열어 봤는지와 마지막 열람 시각이 보이고, **공유 중지**를 누르면 그 링크는 바로 닫힙니다. 담당이거나 참여 중인 프로젝트만 공유할 수 있습니다.

모든 공개 페이지(확인 링크, 진행 공유, 초대 화면, 미디어킷·조건 확인서·결과 보고서) 아래에는 보낸 사람의 소개 링크로 이어지는 **마이웍스 알아보기**가 붙습니다.

## AI 접속 — 클로드를 마이웍스에 연결하기

연동·데이터 → **AI 접속**에서 토큰을 만들면 클로드(또는 다른 AI 도구)가 내 워크스페이스 데이터를 읽고, 변경을 제안할 수 있습니다.

1. **토큰 만들기** — 이름과 권한(읽기 / 쓰기)을 고릅니다. 토큰 원문은 발급 직후 한 번만 보여 주니 복사해 두세요. 읽기 토큰은 묻고 정리하는 용도, 쓰기 토큰은 변경 제안까지 합니다(프로).
2. **클로드 커넥터(MCP)** — 클로드 설정 → 커넥터 → 사용자 지정 커넥터에서 주소 `https://<사이트주소>/mcp`와 인증 헤더 `Authorization: Bearer mw_…`를 넣습니다. 이후 대화에서 "오늘 할 일 정리해 줘", "홍대점 프로젝트 진행률?", "외주 미수금 얼마야?"처럼 물어보면 됩니다.
3. **직접 호출(REST)** — `GET /api/ai/today`, `/api/ai/projects?q=`, `/api/ai/project?id=`, `/api/ai/stores`, `/api/ai/tasks?status=`, `/api/ai/search?q=`, `/api/ai/contacts`, `/api/ai/space`, `/api/ai/outsourcing`, `/api/ai/commerce`, `/api/ai/marketing`, `/api/ai/creator`, `POST /api/ai/propose`. 모두 `Authorization: Bearer mw_…` 헤더를 씁니다.
4. **제안 → 승인** — 쓰기 토큰도 데이터를 바로 고치지 않습니다. `create-task`(업무 추가) · `update-status`(상태·마감 변경) · `add-note`(메모·의견) · `create-contact`(연락처) · `create-job`(외주 안건) · `mk-action`(마케팅 실행안) · `mk-post`(콘텐츠 초안) · `cr-idea`(크리에이터 콘텐츠 아이디어) · `cr-deal`(협찬 건) 제안을 올리면 홈의 **오늘 결정할 것**에서 승인해야 반영됩니다. **AI 제안 자동 반영**에서 고른 종류는 승인 없이 바로 반영됩니다.

- 토큰은 만든 사람의 역할·권한 범위 안에서만 읽습니다. 협력사·현장 근무자는 토큰을 만들 수 없고, 역할이 바뀌거나 비활성화·삭제되면 토큰도 함께 회수됩니다.
- 토큰마다 시간당 60회, 하루 1,500회까지 쓸 수 있습니다. 회수한 토큰은 즉시 막힙니다.
- MCP는 Streamable HTTP(JSON-RPC, POST)만 지원하며, 한 묶음에 도구 호출은 3개까지입니다.

## 운영자 가이드 — 총괄관리

운영자 계정으로 로그인하면 왼쪽 메뉴 맨 아래에 **총괄관리**가 생깁니다(폰에서는 아래 탭의 **관리**). 주소창에 `/admin`을 쳐도 바로 열립니다. 가입 신청이나 새 문의가 들어오면 메뉴 옆 숫자와 홈의 **오늘 결정할 것**으로 알려 줍니다. Cloudflare에 보안 키(`MW_ADMIN_KEY`)를 넣어 두면 총괄관리를 열 때 로그인과 별도로 보안 키를 한 번 더 묻습니다(로그인마다 한 번).

| 탭 | 하는 일 |
|---|---|
| 현황 | 이용 중 워크스페이스, 승인 대기, 프로 수, 예상 월 정기 매출, 이번 달 입금, 새 문의, 전체 계정, 서버 오류(24시간)를 한 화면에 봅니다. **지금 처리할 것**에 가입 신청·문의·프로 기한 임박·만료·서버 오류·백업 알림이 모입니다. 주별 가입 추이와 모듈별 사용 수도 나옵니다. |
| 워크스페이스 | 이름·관리자·아이디·연락처·메모로 검색하고, 상태(이용 중·승인 대기·중지·반려)와 등급(유료 프로·베이직·무료 제공·기한 14일 이내·만료)으로 거릅니다. 이름을 누르면 상세 창이 열립니다 — 계정 목록과 최근 로그인, 기록 개수, 확인 링크 수, AI 토큰, 결제 기록, 운영 메모, 무료 제공 표시, **+1개월 / +1년** 기한 연장, 비밀번호 초기화, 이용 중지·재개, 삭제. |
| 가입·베타 | 승인 대기 목록, **가입 방식**(승인제 · 베타 코드 전용 · 자동 개설 · 신청 마감), 새 워크스페이스의 **시작 등급**(베이직 또는 프로 체험 N일 + 모듈), 고객 문의 연락처, **베타 코드**(이름·등급·기간·모듈·사용 횟수·만료일, 초대 문구 복사). |
| 결제·매출 | 결제 연동 전까지 입금을 손으로 적는 장부입니다. 입금일·금액·방법·항목·이용 기간·세금계산서 여부를 적고, ‘프로 기한 맞추기’를 켜면 기한이 이용 기간 끝까지 늘어납니다(더 늦은 기한은 줄이지 않습니다). 월별 보기, CSV 내려받기, 기한 임박 목록, 예상 월 정기 매출 계산용 가격표. |
| 문의 | 구성원이 앱의 **문의**로 보낸 오류·불편·제안·결제 문의. 답변을 적으면 보낸 사람의 문의 창과 홈 화면에 표시됩니다. 내부 메모는 운영자만 봅니다. |
| 공지 | 점검·업데이트·정책 변경 공지를 게시 기간과 함께 올립니다. 게시 중인 공지는 모든 워크스페이스 화면 위에 띠로 보이고(관리자만 보게 할 수도 있음), 사용자가 닫으면 그 기기에서는 다시 뜨지 않습니다. |
| 기록 | 승인·등급 변경·결제·코드·공지·설정 변경 같은 운영 기록과 서버 오류 기록(최근 200건씩). |
| 계정 지원 | 모든 워크스페이스의 계정을 아이디·이름·워크스페이스·관리자 연락처로 찾습니다(최근 로그인 · 잠긴 계정 · 승인 대기 · 비활성 · 운영팀). 비밀번호를 여러 번 틀려 잠긴 계정의 **잠금 풀기**, 분실한 기기를 위한 **모든 기기 로그아웃**, 한 번만 보이는 **임시 비밀번호** 발급(안내 문구 복사)을 합니다. 업무 내용은 보이지 않습니다. |
| 성장·확산 | 초대(30일 보낸 수·열람률·참여율), 소개로 가입한 워크스페이스, 활성화 단계(가입 → 개설 → 7일 안에 씀 → 프로젝트 → 팀으로 씀 → 유료), 주별 가입 경로(직접·소개), 많이 소개한 워크스페이스, 공유·확인 링크로 이어진 수를 개수로만 봅니다. |
| 운영팀·보안 | 운영자 워크스페이스 구성원에게 총괄관리 역할(운영 매니저 · 고객지원 · 재무 · 보기 전용)을 주고, 역할별 권한 표와 보안 키 상태, 시스템 상태(데이터 구조 버전·표별 개수·최근 세션)를 봅니다. |
| 오픈 준비 | 정식 오픈 전에 운영자가 직접 할 일 27가지(사업자·법적 준비, 결제, 도메인·메일·알림, 보안·운영, 베타·오픈)를 체크하고 메모합니다. 도메인 연결·백업·가입 방식·베타 코드·공지·문의 연락처·보안 키는 시스템이 자동으로 확인합니다. **전체 백업 내려받기**로 플랫폼 전체(모든 워크스페이스·계정·설정)를 JSON 파일 하나로 받습니다. 로그인 세션과 AI 토큰 비밀값은 빠집니다. |

총괄관리에는 워크스페이스별 이름·관리자·연락처·구성원과 계정 목록·최근 활동·등급·기록 **개수**만 보입니다. **각 워크스페이스의 업무 내용(프로젝트·업무 제목, 예약자, 고객, 금액 등)은 운영자도 볼 수 없습니다.** 플랫폼 전체 백업 파일에는 모든 데이터가 들어 있으니 비밀번호가 걸린 곳에 보관하세요. 호스트 예약 동기화와 예전 데이터 가져오기는 운영자 워크스페이스 전용입니다.

### 기능 열기와 비밀값

정보를 새로 받거나 바깥 서비스를 거치는 기능은 운영자가 열어야 사용자에게 보입니다. 개인정보처리방침에 그 내용을 적고, 방침의 시행일이 된 뒤에 여세요. 알림·문자·홈택스에 관한 변경은 2026년 11월 20일에 공지했고 **2026년 12월 21일**부터 시행합니다. 휴대폰 푸시 알림과 홈택스 자동 수집은 그날 뒤에 엽니다.

| 기능 | 여는 방법 | 닫혀 있을 때 |
|---|---|---|
| 휴대폰 푸시 알림 | 총괄관리 → 가입·베타 → **기능 열기**에서 켜기 | 알림함만 씁니다 |
| 문자·알림톡 | Cloudflare 비밀값 `MW_VAULT_KEY`(16자 이상) | ‘준비 중’으로 보이고, 링크 복사·휴대폰 문자 앱으로 대신합니다 |
| 광고 계정 연결(마이마케팅) | `MW_VAULT_KEY` (위와 같은 값) | 보고서 파일 올리기로 대신합니다 |
| 홈택스 자동 수집 | 팝빌 연동 계약 뒤 `POPBILL_LINK_ID`, `POPBILL_SECRET_KEY` (시험 환경은 `POPBILL_TEST=1`) | ‘준비 중’으로 보이고, 홈택스 파일 올리기로 대신합니다 |

비밀값은 Cloudflare 대시보드 → Workers & Pages → myworkspro → Settings → Variables and Secrets → Add에서 **Encrypt**로 넣고, Deployments에서 최근 배포를 **Retry deployment** 합니다.

**열 때 할 일**

1. 지금 — 총괄관리 → **공지**에 개인정보처리방침 변경 안내를 올립니다(홈페이지 공지와 같은 내용). 방침은 홈페이지와 앱 공지 두 곳으로 알리게 되어 있습니다.
2. 2026년 12월 21일 뒤 — 기능 열기에서 ‘휴대폰 푸시 알림’을 켭니다. 켠 뒤에는 홈페이지의 ‘준비 중’ 문구(`src/site/gen.js`의 공지·기본 기능, `src/site/content.js`의 자주 묻는 질문)를 고쳐 다시 만듭니다.
3. 팝빌 연동 계약을 마친 뒤 — 비밀값 두 개를 넣고 시험 환경(`POPBILL_TEST=1`)에서 사업자 하나로 먼저 가져와 봅니다. 확인되면 `POPBILL_TEST`를 지우고 다시 배포합니다.

### 운영팀 — 역할별 권한

혼자 운영하다가 고객 응대나 정산을 맡길 사람이 생기면, 먼저 운영자 워크스페이스의 **설정 → 구성원**에서 그 사람 계정을 만들고 **총괄관리 → 운영팀·보안**에서 역할을 정합니다. 역할이 있는 사람에게만 총괄관리 메뉴가 보이고, 역할에 없는 탭과 버튼은 아예 나오지 않습니다(서버에서도 한 번 더 막습니다).

| 역할 | 할 수 있는 일 |
|---|---|
| 총괄 | 모든 일. 워크스페이스 삭제, 전체 백업, 운영팀 역할 정하기는 총괄만 합니다. |
| 운영 매니저 | 가입 승인·반려, 이용 중지·재개, 등급·모듈, 운영 메모, 프로 기한 연장, 가입 방식·베타 코드, 문의 답변, 공지, 계정 지원, 오픈 준비 체크 |
| 고객지원 | 문의 답변, 공지, 계정 지원(잠금 풀기 · 로그아웃 · 임시 비밀번호) |
| 재무 | 결제 기록·매출·가격표, 프로 기한 연장 |
| 보기 전용 | 보기만 합니다. |

모든 역할은 현황·워크스페이스·성장·확산·기록·오픈 준비를 볼 수 있습니다.

- 총괄은 처음 서버를 설정한 운영자 계정 하나입니다. 운영팀 계정의 잠금 풀기·임시 비밀번호는 총괄만 할 수 있습니다.
- 결제 권한이 없는 역할에는 매출·입금 금액이 내려가지 않습니다. 현황에는 그 자리에 소개 가입·팀 사용 수가 보입니다.
- 모든 처리는 **기록** 탭에 처리한 사람(이름·아이디)과 함께 남습니다.
- 역할을 바꾸거나 빼면 그 사람은 보안 키를 다시 넣어야 하고, 빼면 총괄관리 메뉴가 사라집니다.

### 보안 키(MW_ADMIN_KEY) 넣기

보안 키를 넣으면 두 가지가 됩니다. ① 총괄관리를 열 때 로그인과 별도로 보안 키를 한 번 더 확인합니다(다섯 번 틀리면 그 로그인이 끝납니다). ② 운영자 비밀번호를 잊었을 때 로그인 화면의 **운영자 계정 복구**에서 이 키로 비밀번호를 새로 정할 수 있습니다. 키가 없으면 로그인만으로 총괄관리가 열리고, 운영자 비밀번호를 잊으면 되찾을 방법이 없습니다.

1. [Cloudflare 대시보드](https://dash.cloudflare.com)에 로그인하고 **Workers & Pages**에서 **myworkspro** 프로젝트를 엽니다.
2. **Settings**에서 환경을 **Production**으로 두고 **Variables and Secrets**의 **Add**를 누릅니다.
3. 이름은 `MW_ADMIN_KEY`, 값은 16자 이상 아무도 모르는 문구로 넣고 **Encrypt**(또는 Type의 **Secret**)를 골라 암호화한 뒤 **Save**를 누릅니다. 8자보다 짧으면 꺼진 것으로 봅니다.
4. **Deployments**에서 가장 최근 배포의 **⋯ → Retry deployment**를 누릅니다. 다시 배포되어야 키가 적용됩니다(다음 GitHub 반영 때도 적용됩니다).
5. 총괄관리를 새로고침하면 보안 키를 묻습니다. **운영팀·보안** 탭에서 ‘켜짐’으로 보이면 끝입니다. 키는 비밀번호 관리 앱이나 종이에 따로 적어 두세요. 바꾸고 싶으면 같은 곳에서 값을 바꾸고 다시 배포합니다.

### 운영자 비밀번호를 잊었을 때

로그인 화면 아래 **운영자 계정 복구**를 누르고 보안 키와 새 비밀번호(8자 이상)를 넣습니다. 운영자 계정의 잠금이 풀리고, 예전 로그인은 모든 기기에서 끝납니다. 보안 키를 다섯 번 틀리면 30분 동안 막히고, 시도와 성공은 운영 기록에 남습니다. 일반 사용자의 비밀번호는 이 기능으로 바꿀 수 없습니다 — 워크스페이스 관리자나 총괄관리 **계정 지원**에서 처리합니다.

### 구성원 — 문의와 공지

- 왼쪽 메뉴 아래(폰에서는 **설정** 창 아래)의 **문의**로 운영자에게 오류나 의견을 보냅니다. 하루 20건까지 보낼 수 있습니다.
- 운영자가 답하면 홈의 **오늘 결정할 것**에 ‘문의 답변’이 뜨고, 문의 창의 **보낸 문의**에서 답변을 봅니다.
- 화면 위 공지 띠는 ✕로 닫을 수 있습니다.

## 워크스페이스 관리자 가이드

- **팀원 초대** — 한 사람씩 바로 참여시키려면 **사람 초대**로 사람마다 링크를 보냅니다(승인 없음, 한 번만 사용). 단체방처럼 여러 사람에게 같은 주소를 보낼 때는 **팀 초대 코드**의 초대 링크를 보내고, 신청이 **합류 요청**에 올라오면 역할을 골라 승인하세요. 코드가 밖으로 퍼졌다면 **코드 다시 만들기**로 이전 링크를 막을 수 있습니다.
- **아이디 직접 발급** — **구성원 추가**에서 아이디와 임시 비밀번호를 정해 바로 만들어 줄 수도 있습니다. 근무자라면 같은 창에서 청소 단가와 담당 지점도 정합니다.
- **비밀번호를 잊은 구성원** — 구성원 목록의 **수정**에서 새 비밀번호를 입력해 주면 됩니다.
- **퇴사·계약 종료** — **비활성화**하면 즉시 로그아웃되고 로그인이 막힙니다. **삭제**하면 계정이 지워지고 담당 업무는 미배정으로 바뀝니다. 둘 다 그 사람이 만든 AI 토큰을 함께 회수합니다.
- **백업** — 연동·데이터의 **전체 백업 내려받기**로 주기적으로 받아 두면 언제든 복원하거나 옮길 수 있습니다. 모듈 데이터·연락처·AI 제안 기록이 함께 들어갑니다.

## 로그인 규칙과 보안

- 아이디는 영문 소문자·숫자 4~20자입니다(`.` `_` `-` 사용 가능). 대문자로 입력해도 같은 아이디로 인식합니다.
- 비밀번호는 6자 이상입니다. 서버에는 원문이 아닌 해시(PBKDF2)로만 저장되고, 다른 구성원 기기로 전송되지 않습니다. AI 토큰도 해시로만 저장합니다.
- 비밀번호를 10번 연속 틀리면 그 아이디는 10분간 잠깁니다. 급하면 워크스페이스 관리자에게, 관리자라면 운영자에게 잠금 풀기를 요청하세요.
- 로그인은 마지막 사용 후 30일간 유지됩니다. 비밀번호를 바꾸면 다른 기기는 다시 로그인해야 합니다.
- 각 기기는 마지막 데이터를 보관해 두었다가 다음에 열 때 바로 보여 주고, 바뀐 부분만 받아옵니다. **로그아웃하면 그 기기에 보관된 데이터도 지워지므로**, 공용 PC에서는 사용 후 꼭 로그아웃하세요.
- 협력사 기기로는 예산·매출·재무 내역, 연락처, AI 제안, 반복 업무·템플릿, 다른 사람의 플랜·활동 기록이 아예 전송되지 않습니다. 모듈 화면도 쓰지 않습니다.
- 현장 근무자·시설 담당 기기로는 프로젝트·매장 정보·재무, 다른 사람의 단가, 예약자 이름·연락처·금액, 주문 금액·원가가 전송되지 않습니다. 본인 작업에 필요한 내용만 받습니다.
- 플랜은 역할과 관계없이 본인만 봅니다.
- 가입할 때 이용약관 동의(필수)를 받고 동의 일시를 계정에 기록합니다. 개인정보 처리와 국외 이전(Cloudflare 보관)은 [개인정보처리방침](https://myworks.ai.kr/privacy)에 공개합니다. 반려된 가입 신청은 신청 후 30일, 처리 끝난 문의는 3년이 지나면 총괄관리를 열 때 자동으로 지워집니다.

## 클로드 연동 사용법 (파일 방식)

AI 접속을 쓰지 않아도, 대화 내용을 파일로 받아 반영하는 방식은 그대로 쓸 수 있습니다.

1. 마이웍스의 **연동·데이터** 메뉴에서 "프롬프트 복사"를 누릅니다.
2. 클로드 대화창에 붙여넣으면, 클로드가 대화 내용을 `myworks/v1` 형식의 `.json` 파일로 정리해 줍니다.
3. 받은 파일을 **연동·데이터** 화면에 끌어다 놓으면 미리보기가 뜨고, 확인 후 반영됩니다. 매장(지점)과 연락처도 같은 파일로 한 번에 등록됩니다.

### 가져오기 규칙

- 이름이 같은 프로젝트, 브랜드와 이름이 같은 매장이 이미 있으면 **업데이트**를 기본으로 제안합니다. (새로 만들기·건너뛰기 선택 가능)
- 업무는 제목 기준으로 합쳐지며, 기존 업무가 삭제되지 않습니다.
- `assignee`(업무 담당)와 `manager`(매장 담당)가 구성원 이름과 일치하면 자동 배정되고, 일치하지 않으면 "담당 후보"로 표시됩니다.
- 연락처는 이름이 같으면 비어 있는 칸만 채웁니다.
- 같은 파일을 두 번 올려도 중복 생성되지 않습니다.

### 파일 형식 (myworks/v1)

```json
{
  "format": "myworks/v1",
  "projects": [
    {
      "name": "프로젝트 이름(필수)",
      "brand": "쏘플파티룸",
      "status": "진행중",
      "priority": "높음",
      "startDate": "2026-09-21",
      "dueDate": "2026-10-31",
      "budget": 15000000,
      "summary": "프로젝트 요약 2~3문장",
      "goals": ["목표 1", "목표 2"],
      "notes": "결정 사항·참고 맥락",
      "links": [{ "title": "관련 링크", "url": "https://..." }],
      "tasks": [
        {
          "title": "업무 이름(필수)",
          "detail": "세부 내용",
          "status": "대기",
          "assignee": "담당자 이름",
          "due": "2026-10-08",
          "priority": "보통"
        }
      ]
    }
  ],
  "stores": [
    {
      "name": "매장 이름(필수)",
      "brand": "쏘플파티룸",
      "region": "서울 서대문",
      "address": "",
      "status": "운영중",
      "manager": "담당자 이름",
      "monthlyTarget": 4000000,
      "openDate": "2025-03-14",
      "notes": "지점 관련 메모",
      "tasks": [
        { "title": "에어컨 필터 교체", "status": "대기", "due": "2026-10-04" }
      ]
    }
  ],
  "contacts": [
    { "name": "이름(필수)", "company": "", "phone": "", "email": "", "kind": "거래처", "memo": "" }
  ]
}
```

- 프로젝트 `status`: 대기 · 진행중 · 보류 · 완료
- 업무 `status`: 대기 · 진행중 · 검토 · 완료
- 매장 `status`: 운영중 · 오픈준비 · 휴업 · 종료
- `priority`: 높음 · 보통 · 낮음
- `budget`(프로젝트 예산)과 `monthlyTarget`(매장 월 목표 매출)은 원 단위 숫자입니다.
- 필수는 `projects[].name`, `tasks[].title`, `stores[].name`뿐이며, 나머지는 비워도 됩니다.

`sample-claude.json`이 예시 파일입니다. 그대로 올려서 동작을 확인해 볼 수 있습니다.

## 처음부터 배포하는 경우 (참고)

이미 배포를 마쳤다면 이 절은 건너뛰어도 됩니다.

1. GitHub 저장소에 `app/index.html`, `functions/_middleware.js`, 홈페이지 파일들(필요하면 `README.md`, `sample-claude.json`도)을 올립니다. `functions/_middleware.js`는 `Add file → Create new file`에서 파일 이름 칸에 경로째 입력하면 폴더가 함께 만들어집니다.
2. Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**에서 저장소를 선택합니다. 빌드 설정은 전부 비워 둡니다. (Framework preset: None, Build command 없음, Output directory: `/`)
3. **Storage & Databases → D1 SQL Database → Create Database**로 데이터베이스(예: `myworks-db`)를 만듭니다.
4. Pages 프로젝트의 **Settings → Bindings → Add → D1 database**에서 Variable name을 대문자 `DB`로 적고 방금 만든 데이터베이스를 연결합니다.
5. **Deployments**에서 최신 배포를 `⋯ → Retry deployment`로 다시 배포한 뒤 접속해 운영자 계정을 만듭니다.

### 무료 플랜으로 쓸 수 있는 범위

- Cloudflare 무료 플랜은 하루 요청 10만 건까지 처리합니다(매일 자정 UTC 초기화). 마이웍스는 화면을 보고 있는 동안 15초마다 바뀐 내용을 확인하고, 다른 탭으로 가 있으면 확인을 멈춥니다. 한 사람이 하루 8시간 화면을 켜 두면 약 2천 건이므로, 매일 쓰는 인원이 40명 안팎이 될 때까지는 무료로 충분합니다.
- 마이스토어 데이터는 필요한 기간(기본 오늘 기준 1주 전 ~ 4주 후)만 받아 오고, 다른 기기에서 바뀐 내용이 있을 때만 다시 받습니다. 여러 건을 저장할 때는 한 번에 묶어 처리합니다.
- 거래·마이셀러 데이터도 필요한 범위(진행 중 안건, 최근 30일 주문과 발송 전 주문, 진행 중 발주·반품)만 받아 옵니다. AI 접속(MCP·REST) 호출도 같은 요청 한도에 포함되며, 토큰마다 시간당 60회로 제한됩니다.
- 업무·재무 기록이 수천 건 단위로 쌓인 큰 워크스페이스는 로그인할 때 처리량이 무료 플랜 한도에 가까워질 수 있습니다. 사용 인원이나 데이터가 크게 늘면 Workers 유료 플랜으로 올리는 것을 권합니다.

## 로컬 모드 (서버 없이 쓰기)

`app/index.html` 파일을 그냥 열거나 D1이 연결되지 않은 곳에 올리면 로컬 모드로 동작합니다. 화면 왼쪽 아래 이름 옆 점이 회색이면 로컬 모드입니다.

- 데이터는 그 브라우저에만 저장되고, 회원가입·승인, 모듈, AI 접속, 확인 링크는 나타나지 않습니다. 첫 화면에서 관리자 계정을 만들어 바로 씁니다. 연락처와 검수 요청·승인은 로컬에서도 됩니다.
- 다른 기기로 옮길 때는 연동·데이터의 **전체 백업 내려받기** → 새 기기 첫 화면의 **백업 파일로 시작**을 씁니다.
- 브라우저 데이터를 지우면 함께 사라지므로 주 1회 이상 전체 백업을 권장합니다.
- 휴대폰에서는 브라우저 메뉴의 "홈 화면에 추가"로 앱처럼 설치해 쓸 수 있습니다(클라우드 모드도 동일).
