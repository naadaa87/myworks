# 마이웍스 (MY WORKS)

일이 스스로 굴러가는 업무 시스템.

여러 브랜드와 프로젝트를 동시에 운영하는 대표를 위한 업무·프로젝트 관리 웹앱입니다. 직원·협력업체에게 아이디를 발급해 함께 쓰고, 클로드와의 대화에서 정리한 내용을 파일 하나로 받아 그대로 반영할 수 있습니다.

- 별도 설치나 서버 없이 `index.html` 하나로 동작합니다.
- 브라우저에서 파일을 더블클릭해도 바로 실행됩니다.

---

## 주요 기능

| 메뉴 | 내용 |
|---|---|
| 홈 | 오늘 브리핑(지연·마감·검토·플랜), 오늘의 추진, 통계, 진행 현황, 매장 한눈에, 이달 재무, 최근 활동 |
| 플랜 | 일일·주간·월간 계획을 나만 보는 공간에서 관리. 할 일 체크리스트, 기간별 노트, 해당 기간 마감 업무 자동 표시, 지난 날짜 미완료 항목 "오늘로 가져오기" |
| 프로젝트 | 브랜드별 프로젝트 카드, 상세 화면(업무 목록·목표·메모·링크·의견) |
| 매장 | 오프라인 지점 관리 — 지역·브랜드·상태별 목록, 지점별 업무·정기 점검·메모·의견. 점검 주기가 지나면 자동 경고 |
| 예산·정산 | 프로젝트마다 예산을 정하고 지출·수입을 기록. 잔여 예산과 집행률이 자동 계산되고, 80%를 넘으면 홈에서 경고 |
| 매출·비용 | 매장마다 월 단위로 매출·지출·손익을 기록. 월 목표 매출 대비 달성률과 최근 6개월 매출 추이 표시 |
| 반복 업무 | 정산·세금계산서·재고 확인처럼 주기적인 일을 매주 또는 매월로 등록하면 해당일에 업무가 자동 생성 |
| 업무 템플릿 | "외주 발주 세트" 같은 업무 묶음을 저장해 두고 어느 프로젝트·매장에든 한 번에 투입 |
| 주간 리포트 | 완료·지연·검토 대기와 주간 재무 합계를 텍스트로 복사 — 클로드에 붙여 회고 요청. 재무 내역은 CSV로도 내보내기 |
| 업무보드 | 프로젝트·매장 업무를 한 보드에서 대기 → 진행중 → 검토 → 완료로 관리. 드래그 또는 버튼으로 이동 |
| 구성원 | 관리자가 직원·협력사 아이디 발급, 역할별 접근 범위 자동 적용 |
| 연동·데이터 | 클로드 파일 가져오기, 전체 백업·복원, 프로젝트 선택 공유 파일 |

### 역할별 권한

| 역할 | 프로젝트 | 매장 | 할 수 있는 일 |
|---|---|---|---|
| 관리자 | 전체 | 전체 | 모든 관리 기능, 구성원·매장 발급, 금액 기록 |
| 직원 | 참여·담당 프로젝트 | 전체 매장 | 프로젝트·매장 업무 진행, 점검·금액 기록, 의견 작성 |
| 협력사 | 참여자로 지정된 프로젝트 | 담당·배정된 매장만 | 본인 업무 상태 변경, 점검 기록, 의견 작성 |

예산·매출 등 금액 정보는 관리자와 직원에게만 보이며, 협력사 화면과 공유 파일에는 나타나지 않습니다.

브랜드·회사 목록은 설정에서 편집할 수 있고, 프로젝트·매장 만들기 화면에서 "＋ 직접 입력"으로 그 자리에서 추가할 수도 있습니다.

## 클로드 연동 사용법

1. 마이웍스의 **연동·데이터** 메뉴에서 "클로드 요청 프롬프트 복사"를 누릅니다.
2. 클로드 대화창에 붙여넣으면, 클로드가 대화 내용을 `myworks/v1` 형식의 `.json` 파일로 정리해 줍니다.
3. 받은 파일을 **연동·데이터** 화면에 끌어다 놓으면 미리보기가 뜨고, 확인 후 반영됩니다. 프로젝트뿐 아니라 매장(지점) 목록도 같은 방식으로 한 번에 등록됩니다 — 지점이 많다면 클로드에 "우리 지점 목록을 stores로 정리해줘"라고 요청해 일괄 등록하는 방법을 권합니다.

### 가져오기 규칙

- 이름이 같은 프로젝트, 브랜드와 이름이 같은 매장이 이미 있으면 **업데이트**를 기본으로 제안합니다. (새로 만들기·건너뛰기 선택 가능)
- 업무는 제목 기준으로 합쳐지며, 기존 업무가 삭제되지 않습니다.
- `assignee`(업무 담당)와 `manager`(매장 담당)가 구성원 이름과 일치하면 자동 배정되고, 일치하지 않으면 "담당 후보"로 표시됩니다.
- 같은 파일을 두 번 올려도 중복 생성되지 않습니다.

### 파일 형식 (myworks/v1)

```json
{
  "format": "myworks/v1",
  "projects": [
    {
      "name": "프로젝트 이름(필수)",
      "brand": "쏘플파티룸",
      "status": "진행중",
      "priority": "높음",
      "startDate": "2026-09-21",
      "dueDate": "2026-10-31",
      "budget": 15000000,
      "summary": "프로젝트 요약 2~3문장",
      "goals": ["목표 1", "목표 2"],
      "notes": "결정 사항·참고 맥락",
      "links": [{ "title": "관련 링크", "url": "https://..." }],
      "tasks": [
        {
          "title": "업무 이름(필수)",
          "detail": "세부 내용",
          "status": "대기",
          "assignee": "담당자 이름",
          "due": "2026-10-08",
          "priority": "보통"
        }
      ]
    }
  ],
  "stores": [
    {
      "name": "매장 이름(필수)",
      "brand": "쏘플파티룸",
      "region": "서울 서대문",
      "address": "",
      "status": "운영중",
      "manager": "담당자 이름",
      "monthlyTarget": 4000000,
      "openDate": "2025-03-14",
      "notes": "지점 관련 메모",
      "tasks": [
        { "title": "에어컨 필터 교체", "status": "대기", "due": "2026-10-04" }
      ]
    }
  ]
}
```

- 프로젝트 `status`: 대기 · 진행중 · 보류 · 완료
- 업무 `status`: 대기 · 진행중 · 검토 · 완료
- 매장 `status`: 운영중 · 오픈준비 · 휴업 · 종료
- `priority`: 높음 · 보통 · 낮음
- `budget`(프로젝트 예산)과 `monthlyTarget`(매장 월 목표 매출)은 원 단위 숫자입니다.
- 필수는 `projects[].name`, `tasks[].title`, `stores[].name`뿐이며, 나머지는 비워도 됩니다. `projects`와 `stores`는 둘 중 하나만 있어도 됩니다.

`sample-claude.json`이 예시 파일입니다. 그대로 올려서 동작을 확인해 볼 수 있습니다.

## 클라우드 전환 — 어디서든 로그인해서 쓰기

기본 상태(로컬 모드)에서는 데이터가 각 브라우저에만 저장됩니다. 아래대로 Cloudflare **D1 데이터베이스**를 연결하면 클라우드 모드로 바뀌어, 어떤 컴퓨터·휴대폰에서든 같은 주소로 로그인만 하면 전원이 동일한 데이터를 실시간으로 보고 함께 작업합니다. 전 과정이 화면 클릭만으로 되며, 명령어 입력은 없습니다.

1. **서버 파일 올리기** — GitHub 저장소에서 `Add file → Create new file`을 누르고 파일 이름 칸에 `functions/_middleware.js` 를 그대로 입력합니다(폴더가 자동으로 만들어집니다). 함께 받은 `_middleware.js` 파일을 메모장으로 열어 내용 전체를 붙여넣고 Commit 합니다.
2. **D1 만들기** — Cloudflare 대시보드 → 왼쪽 메뉴 **Storage & Databases → D1 SQL Database → Create Database**. 이름은 `myworks-db` 정도로 짓고 만들면 끝입니다. 표(테이블)는 앱이 첫 접속 때 알아서 만드니 SQL을 입력할 필요가 없습니다.
3. **Pages에 연결** — Workers & Pages에서 마이웍스 Pages 프로젝트를 열고 **Settings → Bindings → Add → D1 database**. Variable name에 반드시 대문자로 `DB` 라고 쓰고, 방금 만든 데이터베이스를 선택해 저장합니다.
4. **재배포** — 같은 프로젝트의 **Deployments** 탭에서 최신 배포의 `⋯ → Retry deployment`를 누릅니다. (GitHub에서 아무 파일이나 수정해 커밋해도 자동 재배포됩니다)
5. **첫 접속** — 사이트를 열면 클라우드 모드의 설정 화면이 나옵니다. 새로 시작해도 되고, 기존에 쓰던 데이터가 있다면 **"백업 파일로 시작"**으로 로컬에서 받아 둔 전체 백업(.json)을 올린 뒤 본인 아이디로 로그인하면 데이터가 서버로 그대로 이전됩니다.

### 클라우드 모드에서 달라지는 것

- 구성원 각자가 자기 기기에서 아이디·비밀번호로 로그인하면 바로 같은 워크스페이스입니다. 공유 파일 왕복이 더는 필요 없습니다.
- 화면 왼쪽 아래 이름 옆의 점이 상태 표시입니다 — 초록: 연결됨 / 노랑: 오프라인(저장은 안전, 연결되면 자동 반영) / 회색: 로컬 모드.
- 비밀번호는 서버에 해시로만 저장되고, 다른 구성원 화면으로 전송되지 않습니다.
- 무료 요금제 범위(D1·Pages Functions 무료 한도)로 소규모 팀 사용에는 충분합니다.
- 클라우드 모드에서도 주 1회 전체 백업 습관은 유지하시길 권합니다. 백업 파일 하나면 언제든 복원·이전이 됩니다.

## 배포 방법 (GitHub → Cloudflare Pages)

1. GitHub 저장소에 `index.html`(필요하면 `README.md`, `sample-claude.json`도)을 올립니다.
2. Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**에서 해당 저장소를 선택합니다.
3. 빌드 설정은 전부 비워 둡니다. (Framework preset: None, Build command 없음, Output directory: `/`)
4. **Save and Deploy**를 누르면 `프로젝트명.pages.dev` 주소가 발급됩니다.

이후 GitHub에 파일을 수정해 올릴 때마다 자동으로 다시 배포됩니다. Git 연결 없이 Cloudflare Pages의 **Direct Upload**(zip 업로드)로 올려도 동일하게 동작합니다.

## 데이터 저장 방식과 한계

- 모든 데이터는 **접속한 브라우저의 localStorage**에 저장됩니다. 서버에 저장되지 않습니다.

### 다른 컴퓨터·노트북에서 쓰기 (로컬 모드)

클라우드 전환을 마쳤다면 이 절차는 필요 없습니다 — 어느 기기에서든 로그인만 하면 됩니다. 아래는 로컬 모드로 쓰는 경우입니다.

새 기기에서 처음 열면 데이터가 없어 "워크스페이스 만들기" 화면이 뜹니다. 새로 만들지 말고 다음 순서로 옮기세요.

1. 쓰던 기기의 **연동·데이터 → 전체 백업 내려받기**로 .json 파일을 받습니다.
2. 새 기기에서 사이트를 열고 첫 화면의 **"이미 만든 워크스페이스가 있어요 — 백업 파일로 시작"**을 눌러 그 파일을 선택합니다.
3. 로그인 화면이 뜨면 본인 아이디로 로그인합니다. 구성원·매장·재무까지 전부 그대로 들어옵니다.

이후 두 기기는 각자 따로 저장되므로 실시간으로 같아지지는 않습니다. 한 기기를 기준으로 정해 두고, 다른 기기에서 작업했다면 백업 → 기준 기기에서 복원(연동·데이터 → 백업 파일로 복원)하는 방식으로 맞추는 것이 안전합니다. 여러 사람이 항상 같은 데이터를 보게 하려면 로드맵의 서버 전환(Cloudflare D1 + Workers)이 답입니다.
- 따라서 기기·브라우저가 다르면 데이터가 각자 따로 존재합니다. 구성원과의 공유는 **연동·데이터 → 공유 파일 내보내기/가져오기**로 처리합니다. 프로젝트와 매장을 함께 골라 내보낼 수 있고, 같은 항목은 겹치지 않게 합쳐집니다. 금액 내역은 공유 파일에 포함되지 않고, 전체 백업에만 저장됩니다.
- 브라우저 데이터를 지우면 함께 사라지므로, **주 1회 이상 전체 백업**을 권장합니다.
- 휴대폰에서는 브라우저 메뉴의 "홈 화면에 추가"로 앱처럼 설치해 쓸 수 있습니다.
- 로그인은 팀 내부용 간편 인증 수준입니다. 중요한 기밀 정보는 담지 않는 것을 권장합니다.

### 로드맵

- Cloudflare **D1 + Workers**를 붙이면 실시간 다중 사용자 동기화가 가능합니다. 현재 구조(데이터 전체가 하나의 JSON)를 그대로 서버로 옮기는 방식이라, 지금 쌓은 데이터를 백업 파일로 이전할 수 있습니다.

## 파일 구성

```
index.html                 앱 전체 (HTML + CSS + JS 단일 파일)
functions/_middleware.js   클라우드 모드 서버 (Cloudflare Pages Functions + D1)
sample-claude.json         클로드 연동 형식 예시 파일
README.md                  이 문서
```
