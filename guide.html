지금 운영 중인 버전(v4) 기준입니다. 메뉴 이름이 바뀌는 재편(마이스토어·마이셀러로의 통합)은 반영될 때마다 공지와 함께 이 페이지를 갱신합니다.

이용 흐름

단계 누가 하는 일
1. 회원가입 새 사용자 첫 화면 회원가입에서 워크스페이스 이름·이름·아이디·비밀번호·연락처를 입력해 개설을 신청합니다.
2. 승인 운영자 운영 메뉴(운영 콘솔)에서 신청 내용을 확인하고 승인합니다. 새 워크스페이스는 베이직으로 시작합니다.
3. 로그인 사용자 승인되는 즉시, 어느 기기에서든 같은 아이디·비밀번호로 로그인해 본인 워크스페이스를 씁니다.
4. 팀원 합류 워크스페이스 관리자 사람 메뉴의 초대 링크를 보내면, 받은 사람이 회원가입 후 합류를 요청합니다. 관리자가 역할(직원·현장 근무자·시설 담당·협력사)을 정해 승인합니다. 아이디를 바로 만들어 줄 수도 있습니다.
5. 프로 전환 운영자 운영 콘솔 → 해당 워크스페이스의 등급·모듈에서 프로로 올리고 쓸 모듈과 기한을 정합니다.

승인 전에는 로그인되지 않고, 화면에 "가입 승인을 기다리는 중입니다"라고 안내됩니다. 워크스페이스끼리는 데이터가 완전히 분리되어 서로 보이지 않습니다.

모듈 켜고 끄기

워크스페이스 관리자가 설정 → 등급과 모듈에서 스위치를 켜면 왼쪽 메뉴에 바로 추가됩니다. 끄면 메뉴만 사라지고 데이터는 남습니다. 모듈 데이터는 전체 백업에 함께 들어가고, 복원하면 같이 돌아옵니다.

홈 — 오늘 결정할 것

홈 맨 위에 승인·확인이 필요한 일이 모입니다. 여기서 바로 처리하면 됩니다.

검수 흐름 (납품 확인)

  1. 담당자(직원·협력사)가 업무에서 검수 요청을 누르고 납품물 링크("제목 | 링크")와 메모를 적습니다. 업무는 검토 상태가 됩니다.
  2. 관리자, 또는 그 프로젝트·매장에서 일하는 직원이 홈이나 업무 목록에서 승인(완료 처리) 또는 보완 요청(사유 전달)을 합니다. 본인이 담당한 업무는 본인이 승인할 수 없습니다.
  3. 고객에게 직접 확인받으려면 고객 확인 링크를 만들어 보냅니다. 고객이 링크에서 "결과물을 확인했습니다"를 누르면 업무가 완료되고, 수정을 요청하면 사유와 함께 담당자에게 돌아갑니다.

AI가 만든 업무·연락처에는 AI 표시가 붙습니다.

사람 — 구성원과 연락처

  • 구성원 — 로그인해서 함께 일하는 사람. 초대 링크·합류 승인·아이디 발급은 이전과 같습니다.
  • 연락처 — 고객·거래처·외주 등 바깥 사람. 이름·회사·연락처·이메일·구분·메모를 두고 검색합니다. 아웃소싱의 안건·견적·청구서는 여기 등록한 고객을 기준으로 만들어지고, 클로드에게 "하나디자인 연락처 알려 줘"처럼 물어볼 수 있습니다. 연락처는 관리자·직원만 보고, 협력사·현장 근무자 기기로는 전송되지 않습니다.

스페이스 — 공간 운영

파티룸·스터디룸처럼 예약으로 돌아가는 공간을 위한 기능입니다. 왼쪽 메뉴 스페이스에서 씁니다.

예약 → 청소 일정 자동 생성 → 배정(개별·일괄) → 근무자 체크리스트 제출 → 관리자 확인(완료·보완 요청) → 손익

시작하기 (처음 한 번)

  1. 운영 지점 켜기 — 스페이스 → 설정 → 운영 지점. 마이웍스 매장 가운데 예약·청소를 관리할 곳만 스페이스를 켭니다. 지점마다 지역(일괄 배정 권역)·기본 담당·지점 코드·별칭·운영시간·청소 규칙·특이규칙을 정할 수 있습니다. 여기서 ＋ 새 지점을 누르면 매장도 함께 만들어집니다.
  2. 예약 넣기 — 예약 달력에서 칸을 누르거나, 예약 엑셀을 올리거나, 호스트 동기화를 켭니다. 예약이 들어오면 청소 일정이 바로 생깁니다.
  3. 근무자 초대 — 사람 메뉴에서 역할을 현장 근무자로 발급하고, 청소 건당 단가와 담당 지점을 정합니다. 근무자는 같은 사이트 주소로 휴대폰에서 로그인합니다.

공통 체크리스트 20개 항목(증빙·쓰레기·주방·실내·화장실·기기·마무리)은 처음 열 때 자동으로 들어갑니다. 스페이스 → 청소 → 체크리스트 항목에서 고치거나, 지점별 특별 항목을 더할 수 있습니다.

청소 일정이 만들어지는 규칙

  • 낮타임만 있으면 낮 이용 종료 후 정식 청소, 같은 날 밤타임이 이어지면 그 사이에 중간 정리(빠른 정리 항목)가 잡힙니다. 같은 고객이 이어서 쓰면 중간 정리를 생략할 수 있습니다.
  • 밤타임은 다음 날 아침 퇴실 후, 올데이는 이용 종료 후 정식 청소입니다.
  • 다음 입실 시각에서 입실 전 버퍼(기본 30분)를 뺀 시각까지가 청소 가능 시간입니다. 이 시간이 표준 소요(기본 120분)보다 짧으면 긴급, 다음 입실이 다른 날이면 "~10/8 13:30까지 완료"처럼 마감으로 표시됩니다.
  • 예약에 확인 메모를 걸면 해당 청소에 "확인 후 진행" 배너가 뜹니다. 근무자에게는 메모 내용이 보이지 않습니다.
  • 담당은 카드에서 지정한 사람 → 그날 권역 일괄 배정 → 지점 기본 담당 순으로 정해집니다.

근무자 화면

현장 근무자로 로그인하면 오늘 청소와 시설 신고 메뉴가 보입니다(커머스를 켰다면 오늘 발송도 함께). 오늘 필수 확인사항을 읽고 확인했습니다를 누르면 관리자 보드에 읽음이 남습니다. 카드를 누르면 체크리스트가 열리고, 체크한 내용은 바로 자동 저장됩니다. 청소 완료 제출을 누르면 관리자 확인 대기로 넘어가고, 보완 요청이 오면 사유와 함께 다시 표시됩니다.

근무자에게는 배정됐거나 아직 담당이 없는 청소만 보이고, 담당 지점을 정해 두면 그 지점 일만 보입니다. 예약자 이름·연락처·결제 금액·확인 메모는 근무자 기기로 아예 전송되지 않습니다. 같은 고객이 이어서 쓰는지 판단하는 값만, 매번 다르게 바뀌는 형태로 보냅니다.

시설 담당은 현황·시설 관리·청소 현황을 보고, 시설 이슈의 상태와 처리 기록을 관리합니다.

예약 넣는 세 가지 방법

  1. 예약 달력 — 칸을 누르면 그 지점의 낮·밤·올데이 예약이 바로 들어갑니다(검정). 다시 누르면 상세 정보와 삭제가 나옵니다. 상세 예약 추가에서는 예약자·연락처·금액·예약번호까지 넣습니다.
  2. 엑셀 업로드 — 예약 사이트에서 받은 월별 엑셀(xlsx)을 올리면 이용일·지점·구분·결제금액 열을 자동으로 찾습니다. 지점 이름이 다르면 화면에서 골라 맞춥니다. 해당 월 교체는 그 달의 기존 엑셀분만 바꾸고, 기존에 추가는 같은 예약번호를 건너뜁니다.
  3. 호스트 동기화 — HOSTDB를 연결하면 오늘 기준 35일 전 ~ 90일 후 예약을 자동으로 맞춥니다. 관리자가 스페이스를 열 때 마지막 동기화가 12시간을 넘었으면 한 번 돌고, 예약 달력과 설정 → 연결의 버튼으로 바로 실행할 수도 있습니다. 예약 사이트에서 취소된 예약은 여기서도 사라집니다. 지점 이름이 달라 못 맞춘 예약은 운영 지점의 **지점 코드(S코드)**나 별칭에 그 이름을 넣으면 다음부터 연결됩니다.

엑셀·동기화로 들어온 예약은 달력에 주황색으로 표시되고, 내용은 원본에서 고칩니다. 예약번호가 N으로 시작하면 네이버, BF로 시작하면 자체 예약으로 집계합니다.

마이웍스와 연결되는 부분

  • 매장 = 지점 — 스페이스를 켠 매장이 곧 지점입니다. 매장 상세 화면에 이달 예약·예약 매출·오늘 청소·시설 이슈 카드가 붙고, 꺼져 있으면 그 자리에서 켤 수 있습니다.
  • 구성원 = 근무자 — 구성원 수정 창에서 청소 건당 단가와 담당 지점을 정합니다. 단가는 손익의 인건비 자동 계산(제출·확인 완료 청소 × 단가, 기본 15,000원)에 쓰입니다.
  • 재무로 보내기 — 손익 → 비용·손익에서 그 달 지점별 매출과 비용(임대료·관리비·소모품·통신비·기타·수수료·인건비)을 각 매장의 매출·비용 기록으로 옮깁니다. 같은 달을 다시 보내면 스페이스 집계분만 새 값으로 바뀝니다.
  • 홈 화면 — "오늘의 공간 운영" 카드에 오늘 청소, 긴급, 담당 미정, 확인 대기, 시설 이슈가 모여 있습니다.
  • 주간 리포트 — 연동·데이터의 주간 리포트 복사에 예약 건수·매출, 청소 확인 현황, 진행 중 시설 이슈가 함께 들어갑니다.
  • 최근 활동 — 청소 제출·확인, 시설 이슈 신고·완료, 엑셀 업로드, 동기화가 활동 기록에 남습니다.
  • 배정된 업무 — 마이웍스 업무를 근무자에게 배정하면 근무자 화면 아래에 함께 보이고, 체크하면 완료됩니다.
  • 백업 — 전체 백업 파일에 스페이스 데이터가 함께 들어가고, 복원하면 같이 돌아옵니다. 업무 데이터 초기화를 하면 예약·청소 기록도 지워지고 운영 시간과 공통 체크리스트는 남습니다.

예전 마이웍스 스페이스 데이터 가져오기

따로 배포해 쓰던 공간관리 시스템의 데이터를 운영자 워크스페이스로 옮깁니다.

  1. 위 표대로 SPACEDB 바인딩을 예전 DB(예: ssople-ops)에 연결하고 다시 배포합니다.
  2. 운영자 계정으로 스페이스 → 설정 → 연결 → 가져올 내용 확인 → 가져오기 시작.
  3. 지점·계정·체크리스트·채널·비용·일괄 배정·브리핑·시설 이슈·예약·청소 기록이 차례로 옮겨집니다. 같은 이름의 매장·구성원은 그대로 이어 쓰고, 없는 것은 새로 만듭니다. 여러 번 눌러도 중복으로 들어가지 않습니다.
  4. 새로 만들어진 근무자는 아이디가 없는 상태입니다. 구성원 메뉴에서 수정을 눌러 아이디와 비밀번호를 정해 주면 로그인할 수 있습니다. (예전 비밀번호는 옮기지 않습니다)
  5. 다 옮겼으면 SPACEDB 바인딩은 지워도 됩니다.

아웃소싱 — 프리랜서 외주 관리

왼쪽 메뉴 아웃소싱. 관리자·직원이 씁니다.

문의 → 안건 등록 → 견적(확인 링크로 승인) → 진행·납품 → 청구서(확인 링크) → 입금 확인 → 재무 기록
화면 내용
현황 진행 중 안건, 견적 회신 대기, 미수금, 이달 입금. 견적 수정 요청·입금 기한 지난 건을 맨 위에
안건 외주 한 건. 고객(연락처)·납기·예상 금액·요청 내용·계약 조건(범위·수정 횟수·대금 조건). 상태: 문의 → 견적 → 진행 → 납품 → 청구 → 완료 / 보류
견적 항목·수량·단가를 넣으면 공급가·부가세·합계가 바로 계산됩니다. 설정의 단가표에서 골라 넣을 수 있습니다. 저장하고 발송 처리를 누르면 확인 링크가 만들어집니다. 고객이 승인하면 안건이 진행으로 바뀌고 승인 견적이 계약 조건에 기록됩니다. 승인된 견적은 고칠 수 없고(무효 처리만), 조건이 바뀌면 새 견적을 만듭니다.
청구·입금 청구서를 만들면 세금 처리(부가세 10% 별도 / 3.3% 원천징수 / 없음)에 따라 받을 금액이 계산되고 확인 링크가 만들어집니다. 입금 확인을 누르면 안건의 청구가 모두 입금됐을 때 자동으로 완료가 됩니다. 재무에 기록을 누르면 마이웍스 재무에 수입으로 들어갑니다.
설정 보내는 사람(이름·상호·연락처·사업자 구분·사업자번호), 입금 계좌, 계약서 양식 링크, 견적서 기본 안내문, 단가표, 플랫폼 수수료율(크몽·위시켓 등, 참고용)

클로드가 create-job 제안으로 안건을 올릴 수도 있습니다. 연락처에 없는 고객 이름이면 승인할 때 연락처가 함께 만들어집니다.

커머스 — 상품 판매 운영

왼쪽 메뉴 커머스. 관리자·직원은 전체를, 현장 근무자(발송 담당)는 오늘 발송 화면만 씁니다.

주문(엑셀 업로드·직접 입력) → 포장·발송(송장) → 재고 차감 → 문의 답변 → 채널별 손익 → 재무 기록
화면 내용
현황 발송할 주문, 답할 문의, 재고 부족 상품, 이달 매출(채널별)
주문 기간·상태·채널·검색. 엑셀 업로드는 스마트스토어·쿠팡 등에서 받은 주문 엑셀의 열 이름을 보고 자동으로 맞추고(수동 조정 가능), 채널별로 맞춤을 기억합니다. 추가는 같은 주문번호를 건너뛰고, 해당 월 교체는 그 달의 기존 엑셀분만 바꿉니다. 송장번호가 있는 행은 발송 상태로 들어갑니다. CSV 내보내기도 됩니다.
상품·재고 상품명·SKU·판매가·매입가·재고·안전 재고. 주문의 상품명이 같으면 자동 연결됩니다. 발송하면 재고가 빠지고, 발송 뒤 취소·반품이면 되돌아옵니다. 재고 조정으로 실사 수량을 맞춥니다(+5, -3 같은 입력도 됩니다).
문의 고객 문의와 답변 기한(기본 다음 날). 답변을 적고 답변 완료로 처리합니다.
손익 월별·채널별 매출(취소·반품 제외), 채널 수수료(설정의 수수료율), 배송비, 상품 원가(연결된 상품의 매입가 × 수량), 광고비·기타(직접 입력) → 손익. 이달 손익을 재무에 기록으로 마이웍스 재무에 수입·지출로 넣습니다.
설정 판매 채널(수수료율·정산 주기), 기본 배송비, 운영 메모. 기본 채널은 네이버 스마트스토어·쿠팡·자사몰·오프라인입니다.

발송 담당 화면

현장 근무자로 로그인하면 오늘 발송에 신규·포장 주문이 카드로 보입니다. 카드를 열어 포장 완료, 송장번호·택배사를 적고 발송 완료를 누릅니다. 최근 이틀 안에 발송한 주문은 아래에 남아 송장을 고칠 수 있습니다. 금액·매입가·정산 정보는 발송 담당 기기로 전송되지 않고, 수령인 이름·연락처·주소는 발송 전 주문과 막 발송한 주문에만 내려옵니다.

확인 링크 — 계정 없는 상대에게 보내기

견적서·청구서·납품물은 확인 링크(사이트주소/app/#/link/…, 짧게는 사이트주소/link/…)로 보냅니다. 받은 사람은 로그인 없이 내용을 보고 승인 / 확인 / 수정 요청만 할 수 있습니다.

  • 링크는 30일(견적은 만들 때 정한 기간) 동안 유효하고, 같은 대상으로 새 링크를 만들면 이전 링크는 닫힙니다.
  • 상대가 누른 결과는 보낸 사람의 마이웍스에 바로 기록되고(활동 기록, 홈의 결정할 것), 수정 요청 사유도 함께 들어옵니다.
  • 수정 요청이 온 견적은 고친 뒤 같은 링크로 다시 승인받을 수 있습니다. 납품 확인도 담당자가 다시 검수 요청하면 같은 링크로 다시 답할 수 있습니다.
  • 링크 페이지에는 고객의 연락처, 내부 메모, 다른 업무 정보가 나가지 않습니다.

AI 접속 — 클로드를 마이웍스에 연결하기

연동·데이터 → AI 접속에서 토큰을 만들면 클로드(또는 다른 AI 도구)가 내 워크스페이스 데이터를 읽고, 변경을 제안할 수 있습니다.

  1. 토큰 만들기 — 이름과 권한(읽기 / 쓰기)을 고릅니다. 토큰 원문은 발급 직후 한 번만 보여 주니 복사해 두세요. 읽기 토큰은 묻고 정리하는 용도, 쓰기 토큰은 변경 제안까지 합니다(프로).
  2. 클로드 커넥터(MCP) — 클로드 설정 → 커넥터 → 사용자 지정 커넥터에서 주소 https://<사이트주소>/mcp와 인증 헤더 Authorization: Bearer mw_…를 넣습니다. 이후 대화에서 "오늘 할 일 정리해 줘", "홍대점 프로젝트 진행률?", "외주 미수금 얼마야?"처럼 물어보면 됩니다.
  3. 직접 호출(REST) — GET /api/ai/today, /api/ai/projects?q=, /api/ai/project?id=, /api/ai/stores, /api/ai/tasks?status=, /api/ai/search?q=, /api/ai/contacts, /api/ai/space, /api/ai/outsourcing, /api/ai/commerce, POST /api/ai/propose. 모두 Authorization: Bearer mw_… 헤더를 씁니다.
  4. 제안 → 승인 — 쓰기 토큰도 데이터를 바로 고치지 않습니다. create-task(업무 추가) · update-status(상태·마감 변경) · add-note(메모·의견) · create-contact(연락처) · create-job(외주 안건) 제안을 올리면 홈의 오늘 결정할 것에서 승인해야 반영됩니다. AI 제안 자동 반영에서 고른 종류는 승인 없이 바로 반영됩니다.
  • 토큰은 만든 사람의 역할·권한 범위 안에서만 읽습니다. 협력사·현장 근무자는 토큰을 만들 수 없고, 역할이 바뀌거나 비활성화·삭제되면 토큰도 함께 회수됩니다.
  • 토큰마다 시간당 60회, 하루 1,500회까지 쓸 수 있습니다. 회수한 토큰은 즉시 막힙니다.
  • MCP는 Streamable HTTP(JSON-RPC, POST)만 지원하며, 한 묶음에 도구 호출은 3개까지입니다.

운영자 가이드

운영자 계정으로 로그인하면 왼쪽 메뉴에 운영이 추가됩니다. 새 가입 신청이 들어오면 메뉴 옆 숫자와 홈의 오늘 결정할 것으로 알려 줍니다.

작업 설명
승인 · 반려 신청자 이름·아이디·연락처·가입 목적을 보고 결정합니다. 승인하면 그 사람은 바로 로그인할 수 있습니다.
등급·모듈 워크스페이스마다 베이직/프로, 쓸 모듈, 프로 기한, 한도(브랜드·구성원·토큰 수)를 정합니다. 비우면 등급 기본값(베이직 2/2/1, 프로 무제한/10/20)이 적용됩니다.
이용 중지 · 재개 중지하면 그 워크스페이스 구성원 전원이 즉시 로그아웃되고, 재개할 때까지 로그인할 수 없습니다. 데이터는 그대로 남습니다.
관리자 비밀번호 초기화 워크스페이스 관리자가 비밀번호를 잊었을 때 새 비밀번호를 정해 주고 직접 전달합니다.
삭제 워크스페이스와 모든 데이터·계정(모듈 포함)을 지웁니다. 되돌릴 수 없습니다.

운영 콘솔에는 워크스페이스별 이름·관리자·구성원 수·최근 활동·등급만 보입니다. 각 워크스페이스의 업무 내용은 운영자도 볼 수 없습니다. 호스트 예약 동기화와 예전 데이터 가져오기는 운영자 워크스페이스 전용입니다.

워크스페이스 관리자 가이드

  • 팀원 초대 — 사람 메뉴의 초대 링크 복사를 눌러 메신저로 보냅니다. 신청이 합류 요청에 올라오면 역할을 골라 승인하세요. 코드가 밖으로 퍼졌다면 코드 다시 만들기로 이전 링크를 막을 수 있습니다.
  • 아이디 직접 발급 — 구성원 추가에서 아이디와 임시 비밀번호를 정해 바로 만들어 줄 수도 있습니다. 근무자라면 같은 창에서 청소 단가와 담당 지점도 정합니다.
  • 비밀번호를 잊은 구성원 — 구성원 목록의 수정에서 새 비밀번호를 입력해 주면 됩니다.
  • 퇴사·계약 종료 — 비활성화하면 즉시 로그아웃되고 로그인이 막힙니다. 삭제하면 계정이 지워지고 담당 업무는 미배정으로 바뀝니다. 둘 다 그 사람이 만든 AI 토큰을 함께 회수합니다.
  • 백업 — 연동·데이터의 전체 백업 내려받기로 주기적으로 받아 두면 언제든 복원하거나 옮길 수 있습니다. 모듈 데이터·연락처·AI 제안 기록이 함께 들어갑니다.

로그인 규칙과 보안

  • 아이디는 영문 소문자·숫자 4~20자입니다(. _ - 사용 가능). 대문자로 입력해도 같은 아이디로 인식합니다.
  • 비밀번호는 6자 이상입니다. 서버에는 원문이 아닌 해시(PBKDF2)로만 저장되고, 다른 구성원 기기로 전송되지 않습니다. AI 토큰도 해시로만 저장합니다.
  • 비밀번호를 10번 연속 틀리면 그 아이디는 10분간 잠깁니다.
  • 로그인은 마지막 사용 후 30일간 유지됩니다. 비밀번호를 바꾸면 다른 기기는 다시 로그인해야 합니다.
  • 각 기기는 마지막 데이터를 보관해 두었다가 다음에 열 때 바로 보여 주고, 바뀐 부분만 받아옵니다. 로그아웃하면 그 기기에 보관된 데이터도 지워지므로, 공용 PC에서는 사용 후 꼭 로그아웃하세요.
  • 협력사 기기로는 예산·매출·재무 내역, 연락처, AI 제안, 반복 업무·템플릿, 다른 사람의 플랜·활동 기록이 아예 전송되지 않습니다. 모듈 화면도 쓰지 않습니다.
  • 현장 근무자·시설 담당 기기로는 프로젝트·매장 정보·재무, 다른 사람의 단가, 예약자 이름·연락처·금액, 주문 금액·원가가 전송되지 않습니다. 본인 작업에 필요한 내용만 받습니다.
  • 플랜은 역할과 관계없이 본인만 봅니다.

클로드 연동 사용법 (파일 방식)

AI 접속을 쓰지 않아도, 대화 내용을 파일로 받아 반영하는 방식은 그대로 쓸 수 있습니다.

  1. 마이웍스의 연동·데이터 메뉴에서 "프롬프트 복사"를 누릅니다.
  2. 클로드 대화창에 붙여넣으면, 클로드가 대화 내용을 myworks/v1 형식의 .json 파일로 정리해 줍니다.
  3. 받은 파일을 연동·데이터 화면에 끌어다 놓으면 미리보기가 뜨고, 확인 후 반영됩니다. 매장(지점)과 연락처도 같은 파일로 한 번에 등록됩니다.

가져오기 규칙

  • 이름이 같은 프로젝트, 브랜드와 이름이 같은 매장이 이미 있으면 업데이트를 기본으로 제안합니다. (새로 만들기·건너뛰기 선택 가능)
  • 업무는 제목 기준으로 합쳐지며, 기존 업무가 삭제되지 않습니다.
  • assignee(업무 담당)와 manager(매장 담당)가 구성원 이름과 일치하면 자동 배정되고, 일치하지 않으면 "담당 후보"로 표시됩니다.
  • 연락처는 이름이 같으면 비어 있는 칸만 채웁니다.
  • 같은 파일을 두 번 올려도 중복 생성되지 않습니다.

처음부터 배포하는 경우 (참고)

이미 배포를 마쳤다면 이 절은 건너뛰어도 됩니다.

  1. GitHub 저장소에 app/index.html, functions/_middleware.js, 홈페이지 파일들(필요하면 README.md, sample-claude.json도)을 올립니다. functions/_middleware.js는 Add file → Create new file에서 파일 이름 칸에 경로째 입력하면 폴더가 함께 만들어집니다.
  2. Cloudflare 대시보드 → Workers & Pages → Create → Pages → Connect to Git에서 저장소를 선택합니다. 빌드 설정은 전부 비워 둡니다. (Framework preset: None, Build command 없음, Output directory: /)
  3. Storage & Databases → D1 SQL Database → Create Database로 데이터베이스(예: myworks-db)를 만듭니다.
  4. Pages 프로젝트의 Settings → Bindings → Add → D1 database에서 Variable name을 대문자 DB로 적고 방금 만든 데이터베이스를 연결합니다.
  5. Deployments에서 최신 배포를 ⋯ → Retry deployment로 다시 배포한 뒤 접속해 운영자 계정을 만듭니다.

무료 플랜으로 쓸 수 있는 범위

  • Cloudflare 무료 플랜은 하루 요청 10만 건까지 처리합니다(매일 자정 UTC 초기화). 마이웍스는 화면을 보고 있는 동안 15초마다 바뀐 내용을 확인하고, 다른 탭으로 가 있으면 확인을 멈춥니다. 한 사람이 하루 8시간 화면을 켜 두면 약 2천 건이므로, 매일 쓰는 인원이 40명 안팎이 될 때까지는 무료로 충분합니다.
  • 스페이스 데이터는 필요한 기간(기본 오늘 기준 1주 전 ~ 4주 후)만 받아 오고, 다른 기기에서 바뀐 내용이 있을 때만 다시 받습니다. 여러 건을 저장할 때는 한 번에 묶어 처리합니다.
  • 아웃소싱·커머스 데이터도 필요한 범위(진행 중 안건, 최근 30일 주문과 발송 전 주문)만 받아 옵니다. AI 접속(MCP·REST) 호출도 같은 요청 한도에 포함되며, 토큰마다 시간당 60회로 제한됩니다.
  • 업무·재무 기록이 수천 건 단위로 쌓인 큰 워크스페이스는 로그인할 때 처리량이 무료 플랜 한도에 가까워질 수 있습니다. 사용 인원이나 데이터가 크게 늘면 Workers 유료 플랜으로 올리는 것을 권합니다.

로컬 모드 (서버 없이 쓰기)

app/index.html 파일을 그냥 열거나 D1이 연결되지 않은 곳에 올리면 로컬 모드로 동작합니다. 화면 왼쪽 아래 이름 옆 점이 회색이면 로컬 모드입니다.

  • 데이터는 그 브라우저에만 저장되고, 회원가입·승인, 모듈, AI 접속, 확인 링크는 나타나지 않습니다. 첫 화면에서 관리자 계정을 만들어 바로 씁니다. 연락처와 검수 요청·승인은 로컬에서도 됩니다.
  • 다른 기기로 옮길 때는 연동·데이터의 전체 백업 내려받기 → 새 기기 첫 화면의 백업 파일로 시작을 씁니다.
  • 브라우저 데이터를 지우면 함께 사라지므로 주 1회 이상 전체 백업을 권장합니다.
  • 휴대폰에서는 브라우저 메뉴의 "홈 화면에 추가"로 앱처럼 설치해 쓸 수 있습니다(클라우드 모드도 동일).
